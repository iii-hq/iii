## Methods

### registerFunction

Registers a new function with a local handler that runs in the browser
session. HTTP invocation configs are a Node.js SDK feature. The handler's
return value is what the function's observers observe; an event source's
handler returns the event it is called with.

Every call of the function, local or routed, runs the handler and then
goes to the observers that want it (`onObserverMatch`; by default all of
them): the function's `onObserverDeliver` hook delivers it, or iii does,
to those whose `on` and filters match. iii evaluates `on` and filters
where the call is: the engine for a call it routes to this worker, and
the SDK for a call this worker makes to its own function in-process,
through an index of the filters' equality conditions. What the worker
does when the function is observed is set with the hooks (`onObserverAdded`,
`onObserverRemoved`, `onObserverMatch`, `onObserverDeliver`), by id or on
the returned FunctionRef. The SDK acks no observer before this
call returns, so a hook set by id before it, chained on its result, or
set later in the same synchronous block runs for every observer.

A function that sets `args_format`, `private: true`, `observable: false`,
an `onObserverMatch` hook or an `onObserverDeliver` hook needs an engine
with `observe.v2`: it is registered once the connection's engine
advertised it, and against an older engine it stays unregistered (logged
once, `UNSUPPORTED`).

### observe

runs `target`, a registered function. Returns synchronously (also before
the connection is up); the observer is replayed with the same id on
reconnect. Errors show up as state `error` and reject `ready()`; against
an engine without observe that is `UNSUPPORTED`.

### currentInvocation

The invocation the calling code runs in (remote or local handler, or the
function's deliver hook), or `undefined` outside any handler.

Browsers have no `AsyncLocalStorage`: the SDK knows the invocation while
the handler runs synchronously, up to its first `await`; after it this
returns `undefined`. Read it before awaiting, and re-enter it with
ISdk.withInvocation for calls made after.

Code after an `await`, outside ISdk.withInvocation, runs outside any
invocation, but its calls are not treated as new chains: they carry the
`observe_depth` of the deepest invocation running on this page, so the
engine's loop guard (`max_observe_depth`) still stops an observer cycle
whose target awaits before calling back. With several invocations
running this over-counts, and a legitimate chain may stop early. They
carry a `caller` and `traceparent` only when that is unambiguous (one
invocation is running, and it is an observe activation or its function's
deliver hook is running); otherwise none. An invocation that never
settles stops counting as running after 10 minutes (a local call: at its
timeout). Local calls nest the same way: a self-recursion that awaits
before each call goes through the engine past 64 levels, while calls
started together count as one level. A limitation: local calls started in
separate ticks while earlier ones still run also look nested, so a long,
wide fan-out may send some through the engine (same results). While the
socket is closed none is: a function this worker hosts then runs here up
to 256 local calls deep, and past that the call fails at once with
`LOCAL_DEPTH_EXCEEDED` (a runaway recursion must not freeze the page).

**Signature**

```typescript
currentInvocation() => InvocationContext | undefined
```

#### Example

```typescript
worker.registerFunction('ui::checkout', async (cart) => {
  const inv = worker.currentInvocation() // { function_id, invocation_id, caller, observe_depth, ... }
  const quote = await fetchQuote(cart)
  return worker.withInvocation(inv, () => worker.call({ function_id: 'orders::create', payload: quote }))
})
```

### onObserverDeliver

Delivers each call of a function itself: `hook` receives the call and the
observers that matched it (a snapshot taken when the call started), and
what it returns (or throws) is what the caller gets back. iii delivers
nothing for that function: the hook calls through observers and applies
their filters with `obs.matches(call)`. Without it, iii delivers every
call to the matching observers whose `on` and filters accept it, and the
caller gets the handler's result. `null` removes the hook.

A function with a deliver hook needs an engine with `observe.v2`: against
an older one it stays unregistered, and the SDK logs `UNSUPPORTED` once.

The hook runs in the function's invocation: up to its first `await` in
its scope, and after it as the invocation the page falls back to while it
is the only one running (see ISdk.withInvocation).

### onObserverMatch

Says which observers want each call of a function. By default every
observer wants every call. A predicate `(obs, call) => boolean` is asked
once per active observer per call; `{ observer, call }` key functions are
computed once per observer, when it is accepted, and once per call, and an
observer wants a call when they share a key (the SDK keeps an index). The
observers' `on`, filters, policy and `deliver` still apply. A hook set
while observers are active rebuilds the index from them. `null` removes
the hook.

A function with a match hook needs an engine with `observe.v2`: against
an older one it stays unregistered, and the SDK logs `UNSUPPORTED` once.

#### AddedHook

Runs when an observer of a function is added, before the SDK acks it.
Throw to reject the observer: an ObserveRejection sets the code,
anything else is `OBSERVE_REJECTED`; after 30 s it is rejected with
`OWNER_TIMEOUT`.

```typescript
type AddedHook = (obs: Observer) => void | Promise<void>
```

#### DeliverHook

Delivers each call of a function itself (`onObserverDeliver`): it receives
the call and the observers that matched it (a snapshot taken when the call
started), and what it returns (or throws) is what the caller gets back. A
thrown ObserveRejection, or the error of a call it made, reaches the
caller with its code; any other error as `invocation_failed`. iii delivers
nothing for that function; the hook calls through observers
(`worker.call({ observer, payload })`) and applies their filters with
`obs.matches(call)`. It runs inside the function's invocation, so the calls
it makes have that invocation as their caller.

Browsers have no `AsyncLocalStorage`: the hook runs in the invocation's
scope up to its first `await`. A call it makes after one still has the
invocation as its caller while that invocation is the only one running on
the page; to be sure, read `iii.currentInvocation()` first and re-enter it
with `iii.withInvocation(inv, fn)`. A call through an observer is routed to
the observer's target either way.

```typescript
type DeliverHook = (call: Call<I, O>, observers: readonly Observer[]) => R | Promise<R>
```

#### MatchHook

Which observers want each call of a function (`onObserverMatch`). By
default every observer wants every call. A predicate is asked once per
active observer per call (a throw counts as no match). Keys are computed
once per observer, when it is accepted, and once per call. The observers'
`on`, filters, policy and `deliver` still apply. A host that sends one
observer something of its own (its initial state) calls the function with
`metadata: { for_observer: obs.id }`; the hook gives such a call to that
observer alone (a predicate compares the ids; keys file each observer under
`for_observer:<id>` too).

```typescript
type MatchHook = MatchPredicate<I, O> | MatchKeys<I, O>
```


#### UpdateAppend

Append an element to an array, concatenate a string, or push a new
value at a nested path. The target is the root (when `path` is
omitted, empty, or `[]`), a single first-level key (when `path` is
a non-empty string), or an arbitrary nested location (when `path`
is an array of literal segments). See MergePath.

Engine semantics: missing/null intermediates along a nested path are
auto-created; missing leaves on a nested path always become arrays
(no string-concat tier); existing object/scalar leaves return
`append.type_mismatch`. Each path segment is a literal key,
`["a.b"]` targets a single key named `"a.b"`, not `a → b`.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `path` | [`MergePath`](#mergepath) | No | Optional path to the append target. Accepts a single first-level<br />key (legacy `string`) or an array of literal segments for nested<br />append. See MergePath (the same shape is reused). |

| `value` | `any` | Yes | Value to append. String targets only accept string values. |
