## Initialization

### RegisterWorker

RegisterWorker creates a `Client` for the engine at url and starts the connection lifecycle in the background, returning immediately. An empty url means `EngineURLFromEnv`, as with `New`. It is the idiomatic entry point, matching registerWorker in the Node SDK and register_worker in the Rust SDK. Register functions and observers on the returned client; they are (re)sent on each connection. Call `Client.Close` to stop.

To wait for the first connection (or fail fast on a bad URL), call `Client.Connect` instead of (or after) RegisterWorker; it blocks until connected, ctx is done, or the reconnect budget is exhausted. Use `New` if you want to build a client without starting the connection.

## Methods

### Client.RegisterFunction

RegisterFunction registers a function this worker can handle and returns its handle; `FunctionRef.Unregister` removes it. It may be called before or after Connect; the registration is sent on the next (re)connect. As in the Node, Python and Rust SDKs, an empty id is refused ("id is required") and so is an id this client already registered ("function id already registered"): to replace a function, unregister it first. Pass a single `RegisterFunctionOptions` value for a description, request and response formats, metadata, args_format, private, observable or the local dispatch setting.

The handler's return value is what observers observe. Every call of the function, local or routed, runs the handler and is then delivered to the observers that want it (`Client.OnObservationMatchFor`; by default all of them): by the function's deliver hook (`Client.OnObservationDeliverFor`), or by iii, to those whose capture and filters match. Set hooks by id before registering: the SDK acks no observer before RegisterFunction returns, but a hook set on the returned handle can miss observers already accepted, and is caught up for them.

Handlers read the optional per-invocation metadata sidecar from their ctx with `MetadataFromContext`.

### Client.Call

Call invokes a function. With the default (nil) or an enqueue action it waits for the matching invocation result and returns it, mapping a remote error to `InvocationError` and a missed deadline to `ErrTimeout`. With a `VoidAction` it is fire-and-forget and returns immediately with a nil result. With `CallRequest`.Observer it calls through that observer.

ctx bounds the wait independently of `CallRequest.Timeout`: if ctx is cancelled first, its error is returned and the pending entry is reclaimed. Inside a handler or a deliver hook, pass its ctx: the call then carries that invocation as its caller (and the observe depth), which observers' filters and the engine's loop guard read.

A function this worker hosts runs in-process, without touching the wire, once the engine confirmed it for local dispatch, unless the action is enqueue or Dispatch is `DispatchRemote`. The handler gets its own copy of the payload and the caller its own encoding of the result, except for a `RegisterFunctionOptions`.Private function, whose input and result pass by reference; errors and timeouts look as on the remote path. The call is delivered to the function's observers as a routed one is, from snapshots of the payload and metadata taken when it started. The handler runs on a goroutine of its own, so the caller always returns on its Timeout or ctx deadline, even when the handler blocks and ignores its ctx; the handler then runs to completion (as a remote one would on its worker), its result is discarded, and the call is still counted and delivered. A handler that can block for long should honor its ctx (cancelled on Close), or opt out with `RegisterFunctionOptions`.LocalDispatch.

### Client.Observe

Observe observes a function: when source.FunctionID runs, target runs, for every call that the function's worker delivers to the observer and that passes source.Filters. target is a function registered by some worker (until it is, the observer stays pending). source.Args go to the worker that hosts the function, which reads them in its hooks (a route, a table).

It returns the handle immediately, even before the connection is up; the observer is replayed with the same id on every reconnect. Errors from the engine (INVALID_ARGS, INVALID_FILTER, FORBIDDEN, NOT_OBSERVABLE, SELF_TARGET, the host's rejection, and UNSUPPORTED against an engine without observe) show up as state error and fail `ObserverHandle.Ready`. An observeresult in state error is the engine's refusal of that observe and the handle's final answer: the engine holds no observer for it (it stores nothing for a refused observe, and disposes an observer it holds in error as it answers that observer's replay), the handle is not sent again on a later connection, and its Dispose sends nothing. An observer that turns error after its observe was answered (the host's rejection, OWNER_TIMEOUT) is held by the engine: the handle is replayed, and its Dispose unobserves it. The returned error is for a request that cannot be sent at all: a missing function or target, a blank namespace, args or filters that are not JSON, and an id a handle of this client holds. A handle holds its id until it is disposed (by `ObserverHandle.Dispose` or by the engine); an Observe of a held id sends nothing, leaves the holder alone and returns an \*ObserveRejectionError with code OBSERVER_ID_CONFLICT. Once the holder is disposed the id is free at once. An observer without MaxFires or ExpiresIn that the engine disposed while this worker was away past its grace period (OBSERVER_DISCONNECTED) is not reported disposed: the handle observes again, with the same id, as a new observer (pending, then the engine's answer).

### Client.AddConnectionStateListener

AddConnectionStateListener calls listener with the current `ConnectionState`, then with every later change of state (`StateConnecting`, `StateConnected`, `StateReconnecting`, `StateDisconnected`, `StateFailed`), in the order the changes happen. Calls are made one at a time on a goroutine of the client's own, never on the subscribing goroutine or on the SDK's read loop, so a listener may call any Client method; it should return promptly, since later changes wait for it. A state is reported once per change: the same state is never delivered twice in a row. A listener that panics is logged and keeps its subscription.

It returns the function that unsubscribes listener: changes not yet delivered when it returns are dropped for this listener (a call already under way completes). Calling it more than once does nothing. It mirrors addConnectionStateListener in the browser SDK and add_connection_state_listener in the Python SDK.

### Client.Close

Close shuts the client down at once: it stops the reconnect loop, gives buffered observe reports and telemetry a short, fixed time to go out (250ms for the reports, at most 10s for the telemetry flush), cancels all pending calls with ErrNotConnected, and drops the socket without a closing handshake. It does not send unregister frames (matching the reference SDKs). Use `Client.Shutdown` to wait for the flushes under a deadline of your own and close the socket gracefully.

Close is idempotent and implements io.Closer; it always returns nil. Called while a Shutdown runs, it cuts that Shutdown short (as http.Server.Close does) and returns once it has finished.

### Client.Shutdown

Shutdown shuts the client down gracefully, as the Node SDK's shutdown does, bounded by ctx like http.Server.Shutdown: it stops the reconnect loop, waits until the buffered observe reports and counters are written, stops the worker gauges, flushes and stops the telemetry exporters, cancels all pending calls with ErrNotConnected, and closes the socket with a normal-closure handshake.

When ctx is done before those steps finish, the remaining work is cut short (the socket is closed at once, also when the engine never answers the close handshake) and ctx.Err() is returned; the client is shut down either way and nil means everything was delivered. A `Client.Close` called meanwhile cuts it short the same way, and Shutdown then returns context.Canceled. Like Close it does not send unregister frames. Shutdown is idempotent: a later Shutdown returns once the first shutdown has finished, or ctx.Err() if its own ctx ends first.

**Signature**

```go
type timerArgs struct {
	EveryMs int64 `json:"every_ms"`
}
keyOf := func(everyMs int64) string { return fmt.Sprint(everyMs) }
stops := map[string]chan struct{}{} // one ticker per interval, used on the hook queue only

client.OnObserverAddedFor("timer::on-tick", func(ctx context.Context, obs *iii.Observer) error {
	var args timerArgs
	if err := obs.DecodeArgs(&args); err != nil || args.EveryMs <= 0 {
		return iii.ObserveRejection("INVALID_ARGS", "every_ms must be a positive integer")
	}
	if _, running := stops[keyOf(args.EveryMs)]; running {
		return nil
	}
	stop := make(chan struct{})
	stops[keyOf(args.EveryMs)] = stop
	go func() {
		ticker := time.NewTicker(time.Duration(args.EveryMs) * time.Millisecond)
		defer ticker.Stop()
		for {
			select {
			case <-stop:
				return
			case now := <-ticker.C:
				tick, _ := json.Marshal(map[string]int64{"every_ms": args.EveryMs, "fired_at_ms": now.UnixMilli()})
				if !client.IsObservedFor("timer::on-tick", &iii.Call{Input: tick}) {
					continue
				}
				client.Call(context.Background(), iii.CallRequest{FunctionID: "timer::on-tick", Payload: tick, Action: iii.VoidAction()})
			}
		}
	}()
	return nil
})
client.OnObserverRemovedFor("timer::on-tick", func(ctx context.Context, obs *iii.Observer) {
	var args timerArgs
	_ = obs.DecodeArgs(&args)
	for _, other := range client.Observers("timer::on-tick") {
		var o timerArgs
		if other != obs && other.DecodeArgs(&o) == nil && o.EveryMs == args.EveryMs {
			return // the interval is still observed
		}
	}
	if stop, ok := stops[keyOf(args.EveryMs)]; ok {
		close(stop)
		delete(stops, keyOf(args.EveryMs))
	}
})
client.OnObservationMatchFor("timer::on-tick", iii.MatchKeys(
	func(obs *iii.Observer) []string { // what the observer listens for
		var args timerArgs
		_ = obs.DecodeArgs(&args)
		return []string{keyOf(args.EveryMs)}
	},
	func(call *iii.Call) []string { // what the call is: the tick carries every_ms too
		var tick timerArgs
		_ = json.Unmarshal(call.Input, &tick)
		return []string{keyOf(tick.EveryMs)}
	},
))

if _, err := client.RegisterFunction("timer::on-tick", iii.Identity, iii.FunctionOptions{
	Description: "One call per tick. Observe it with args { every_ms }.",
	ArgsFormat:  json.RawMessage(`{"type":"object","required":["every_ms"],"properties":{"every_ms":{"type":"integer","minimum":1}}}`),
	Private:     true,
}); err != nil {
	log.Fatal(err)
}
```

### OutputStreamToWriter

OutputStreamToWriter returns a stream whose bytes go to w. Closing the stream flushes w (when it has a Flush() error method) and closes it (when it is an `io.Closer`); an abort closes w with the error when it has CloseWithError (an `*io.PipeWriter`) and otherwise leaves it as is, so a truncated stream is never finished as if whole: close it yourself, and remove a partly written file.

When w fails (its Write, Flush or Close returns an error), the stream aborts: nothing more is written to w, the function's next write fails with STREAM_CLOSED, and the call that passed the stream fails with STREAM_ABORTED, "the sink failed: &lt;w's error&gt;", wrapping w's error (errors.Is and errors.As reach it), whatever the function returned.

A call does not wait behind a w.Write that blocks: at the call's timeout, or when its ctx ends, the call returns and the stream is aborted. A Write that never returns (and ignores CloseWithError) keeps the goroutine that called it until it returns.

**Signature**

```go

```

#### Filters

Filters is a declarative filter over input, output, error, caller and metadata, with explicit operators only (the language of the filter subpackage):


#### InputStream

InputStream is the read side of a stream: the bytes (and messages) a function receives.

An InputStream arrives as a field of a handler's input or of a call's result (a "read" ref unmarshals to it), or is built to be sent: `InputStreamFromReader`, `InputStreamFromBytes`, or the input end of `Client.Pipe`. Put it in a call payload or a handler result (as a \*InputStream field, or in a map) and the SDK streams it to the other side.

Read it once, one way: as an `io.Reader` (Read), with `InputStream.ReadAll`, `InputStream.Text`, `InputStream.Lines`, `InputStream.Messages` (text frames) or `InputStream.Frames` (both kinds, in order). Byte reads skip messages. A second reader gets STREAM_IN_USE (`CodeStreamInUse`): Read is one reader across calls, and each of the other methods is a reader of its own. The socket opens on the first read. A stream read to the end returns io.EOF on further reads; one cancelled before its end (`InputStream.Cancel`, `InputStream.Close`, a break out of Lines, Messages or Frames, or the guard below) fails every later read, and a read in flight, with STREAM_CLOSED (`CodeStreamClosed`), never io.EOF.

An abort (its writer failed or called `OutputStream.Abort`) ends a read with an `*InvocationError` of code `CodeStreamAborted`, after the data sent before it.

In a handler, a stream the handler started reading and did not finish is cancelled when the handler returns (a goroutine still reading it gets STREAM_CLOSED: read it before returning); one never read is left alone. One sent on unread (in a call payload or the result) is forwarded: its ref goes, and no byte passes through this worker. One sent on after reading is pumped from where it is. A stream is sent once: sending it twice, or after it was read to the end, fails with STREAM_IN_USE.

A received stream binds to the client that received it (in a handler's input or a call's result); one unmarshalled from JSON that no client received binds to the only `Client` not yet closed, or call `InputStream.Bind`. An InputStream is a handle: copies of it are the same stream. Its methods are safe for concurrent use, but reads are not meant to be shared.

#### MatchHook

MatchHook says which observers want each call of one function; without one, every observer wants every call. Build it with `MatchFunc` (a predicate) or `MatchKeys` (keys the SDK indexes). The observers it matches are what iii delivers the call to, after their capture and filters, or what the function's `DeliverHook` receives. A nil MatchHook, and the zero one, match every observer.

A host that sends one observer something of its own (its initial state) calls the function with metadata \{"for_observer": &lt;observer id&gt;\}, and the hook gives such a call to that observer alone: a predicate compares the ids, and observerKeys also files each observer under "for_observer:&lt;id&gt;", the one key callKeys gives such a call.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `MatchFunc` | func(predicate func(obs *[`Observer`](#observer), call *[`Call`](#call)) bool) *[`MatchHook`](#matchhook) | Yes | MatchFunc is a match hook that asks predicate, once per active observer per call, whether the observer wants the call. A predicate that panics counts as no match, and the SDK logs it once per function. A nil predicate gives a nil MatchHook. |
| `MatchKeys` | func(observerKeys func(obs *[`Observer`](#observer)) []string, callKeys func(call *[`Call`](#call)) []string) *[`MatchHook`](#matchhook) | Yes | MatchKeys is a match hook by keys: an observer wants a call when they share a key, and the SDK keeps an index of the active observers by key instead of asking each of them. observerKeys says what an observer listens for: the SDK computes it once, when the observer is accepted, files the observer under each key and unfiles it when it is removed. An observer whose observerKeys panics is rejected with OBSERVE_REJECTED. callKeys says what a call is: the call matches the observers filed under any of its keys, each once; a callKeys that panics matches nothing, and the SDK logs it once per function. Keys express wildcards by listing them: an observer of every table is filed under "primary\|\*\|insert", and a change matches "primary\|orders\|insert", "primary\|orders\|\*", "primary\|\*\|insert" and "primary\|\*\|\*". A nil function gives a nil MatchHook. |

#### MiddlewareFunctionInput

MiddlewareFunctionInput is the payload the engine sends to the RBAC middleware function (the worker-manager rbac.middleware_function_id) on every function invocation that arrives through the RBAC port. The middleware can inspect, modify or reject the call before it reaches the target function: forward it with `Client.Call`, or return an error to reject it.

It mirrors MiddlewareFunctionInput in the Node and Rust SDKs field for field; the JSON names are the wire contract. Register the middleware with `RegisterFunctionTyped` to receive it decoded, or unmarshal the raw handler payload into it.

When forwarding, note that an empty Namespace means the engine's default namespace, whereas an empty `CallRequest.Namespace` means this worker's own namespace: pass "default" explicitly when Namespace is empty and the worker is namespaced.

```go
raw := []byte(`{"function_id":"orders::create","payload":{"item":"book"},"action":null,"context":{"source":"browser"},"namespace":"default"}`)

var in iii.MiddlewareFunctionInput
if err := json.Unmarshal(raw, &in); err != nil {
	panic(err)
}
fmt.Println(in.FunctionID, in.Namespace, in.Action == nil)
fmt.Println(string(in.Payload), string(in.Context))
```

```go
client := iii.RegisterWorker(iii.DefaultEngineURL)
defer client.Close()

_, _ = iii.RegisterFunctionTyped(client, "auth::middleware",
	func(ctx context.Context, in iii.MiddlewareFunctionInput) (json.RawMessage, error) {
		var payload map[string]any
		if err := json.Unmarshal(in.Payload, &payload); err != nil {
			return nil, err
		}
		payload["_auth"] = in.Context
		data, err := json.Marshal(payload)
		if err != nil {
			return nil, err
		}
		namespace := in.Namespace
		if namespace == "" {
			namespace = "default" // absent means the engine's default namespace
		}
		return client.Call(ctx, iii.CallRequest{
			FunctionID: in.FunctionID,
			Payload:    data,
			Action:     in.Action,
			Namespace:  namespace,
		})
	})
```

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `FunctionID` | `string` | Yes | FunctionID is the ID of the function being invoked. |
| `Payload` | `json.RawMessage` | Yes | Payload is the payload sent by the caller, verbatim. Forward it as `CallRequest.Payload` or decode it to inspect the call. |
| `Action` | *[`CallAction`](#callaction) | No | Action is the routing action of the call, if any (nil for a synchronous request/response). Forward it as `CallRequest.Action` to keep enqueue/void semantics. |
| `Context` | `json.RawMessage` | Yes | Context is the auth context the RBAC auth function returned for this session (AuthResult.context in package helpers/workerconnection), as raw JSON. |
| `Namespace` | `string` | No | Namespace is the target namespace the invocation addressed; forward the call there to stay in the caller's namespace. Empty means the engine's default namespace. |

#### Observer

Observer is an observer as the worker that hosts the observed function sees it (in its hooks and in `Client.Observers`): its args, filters, target and capture. Never its metadata, policy or the observing worker. Its fields are set when it is added; the SDK keeps its own copy of what it reads, so changing them changes nothing but the host's view. The pointer is stable while the engine announces the same view of the observer, so hosts keep it in their own index (expression -&gt; observers, route table).

The engine may announce an observer again with the same args and other filters, target or capture (a replay): it stays the same observer and no hook runs. From then on it is served, and listed by `Client.Observers`, as a new \*Observer with that view; Reject and Accepted act on the observer through either pointer, and pointers handed out earlier keep the view they were made with.

#### OutputStream

OutputStream is the write side of a stream: where a function writes bytes and messages.

An OutputStream arrives as a field of a handler's input or of a call's result (a "write" ref unmarshals to it), or is built around a local sink with `OutputStreamToWriter`: put it in a call payload and the function writes into the sink. The call returns once the sink got the whole stream (and fails with STREAM_ABORTED if the writer aborted it), within the call's timeout. A call whose result holds a stream to write (the function returned a write end) returns without waiting: the caller writes it.

`OutputStream.Write` sends bytes (in binary frames of up to 64 KiB) and `OutputStream.Send` a message (a JSON text frame); each returns once the frame was taken, so a loop of writes follows the reader's pace. End the stream with `OutputStream.Close`, or fail it with `OutputStream.Abort`: the reader then gets an error, not a short stream. A write after either fails with STREAM_CLOSED (`CodeStreamClosed`). `OutputStream.Writer` adapts it to an `io.Writer`. A byte sink made with OutputStreamToWriter takes the bytes only: messages are dropped.

In a handler, the stream is ended when the handler returns: one it used (wrote, sent on, or took a Writer of) is closed when the handler succeeded and aborted when it failed. One it never used is closed when it succeeded and left as is when it failed; in a call through an observer (an HTTP route, say) it is closed only when the handler returned nil (JSON null) and left as is with any other result, as the HTTP worker reads an untouched response with a value as a buffered response. Call `OutputStream.KeepOpen` to keep writing after the handler returned, and then close or abort it yourself.

A received stream binds to the client that received it; see `InputStream` for the rules and `OutputStream.Bind`. An OutputStream is a handle: copies of it are the same stream. Its methods are safe for concurrent use.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `OutputStreamToWriter` | func(w io.Writer) *[`OutputStream`](#outputstream) | Yes | OutputStreamToWriter returns a stream whose bytes go to w. Closing the stream flushes w (when it has a Flush() error method) and closes it (when it is an `io.Closer`); an abort closes w with the error when it has CloseWithError (an `*io.PipeWriter`) and otherwise leaves it as is, so a truncated stream is never finished as if whole: close it yourself, and remove a partly written file. |
| `Abort` | `func(reason string) error` | Yes | Abort fails the stream with reason: the reader's read ends with STREAM_ABORTED (through an engine pipe the reason the reader sees is the engine's). A stream never written is opened first, so its reader always learns of it. Aborting a stream already ended, or being closed, does nothing. Abort does not wait behind a Write or a Send in flight (one blocked by a reader that does not read): that write returns STREAM_CLOSED, and the stream ends at once. |
| `Bind` | func(c *Client) *[`OutputStream`](#outputstream) | Yes | Bind binds a received stream to c: its socket opens on c's engine, with c's handshake headers. Needed only for a stream unmarshalled from JSON that no client received, while several clients are alive. It returns s. |
| `Close` | `func() error` | Yes | Close ends the stream: the reader reads to the end. A stream never written is opened and closed, so its reader sees an empty stream. Closing a stream already ended, or sent on, does nothing. It implements `io.Closer`. |
| `JSONSchema` | `func() *jsonschema.Schema` | Yes | JSONSchema is the schema of a stream to write, for `RegisterFunctionTyped` and `InferSchema`: the ref object, marked with "x-iii-stream": "write". |
| `KeepOpen` | func() *[`OutputStream`](#outputstream) | Yes | KeepOpen keeps the stream open after the handler that received it returns: it is then this code's to close or abort. It returns s. |
| `MarshalJSON` | `func() ([]byte, error)` | Yes | MarshalJSON writes the stream as the ref that takes its place in a payload or a result: its own ref when it was received and not yet used (it is forwarded), else a placeholder the SDK replaces with the ref of a new pipe. Marshal a stream only to send it: a marshalled stream counts as sent. |
| `Send` | `func(ctx context.Context, message any) error` | Yes | Send sends message as a JSON text frame. A json.RawMessage is sent as it is. |
| `UnmarshalJSON` | `func(data []byte) error` | Yes | UnmarshalJSON reads a "write" ref as the stream it stands for (see `InputStream.UnmarshalJSON`). A "read" ref is an error: it is an `InputStream`. |
| `Write` | `func(ctx context.Context, data []byte) error` | Yes | Write writes data, in binary frames of up to 64 KiB, and returns once the socket took them. ctx bounds the write: when it ends mid-write, the socket closes without a close frame and the reader gets an abort. |

TelemetryOptions is what the worker reports about its language, project and framework in the telemetry object of engine::workers::register, shown by engine::workers::list and engine::workers::info. A blank field takes its default. Mirrors TelemetryOptions in the Node and Rust SDKs.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `Language` | `string` | No | Language reported for the worker. Default: the locale of LANG (else LC_ALL) without its encoding, for example "en_US" for LANG=en_US.UTF-8, which is the Node SDK's fallback; omitted when neither variable is set. |
| `ProjectName` | `string` | No | ProjectName is the project the worker belongs to. Default: the last element of the module path in the nearest go.mod, searched from the working directory upwards, skipping a major-version suffix such as /v2; omitted when there is no go.mod. |
| `Framework` | `string` | No | Framework the worker is built with. Default: "iii-go". Surrounding spaces are trimmed. |

#### TypedHandler

TypedHandler is a function handler with a typed request and response. The SDK unmarshals the invocation payload into Req before calling it and marshals the returned Resp into the result, so handlers work with concrete types instead of json.RawMessage.

Per-invocation metadata, when the call carries any, rides on ctx rather than the signature (so adding it is non-breaking): read it with `MetadataFromContext`.

```go
type TypedHandler[Req any, Resp any] func(ctx context.Context, req Req) (Resp, error)
```

### iii/filter

#### Filter

Filter is a validated filter, compiled once into a closure tree. It is immutable and safe for concurrent use.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `Compile` | func(src any) (*[`Filter`](#filter), error) | Yes | Compile validates and compiles a filter given as a Go value. A json.RawMessage or []byte is read as JSON text; any other value is read through encoding/json, so what is validated is exactly what travels on the wire. It returns an \*Error with code INVALID_FILTER when the filter is not valid. |
| `MatchAll` | func() *[`Filter`](#filter) | Yes | MatchAll returns the filter that matches every document (\{\}). |
| `Parse` | func(data []byte) (*[`Filter`](#filter), error) | Yes | Parse validates and compiles a filter given as JSON text. It returns an \*Error with code INVALID_FILTER when the filter is not valid. |
| `ParseNormalized` | func(data []byte) (*[`Filter`](#filter), error) | Yes | ParseNormalized compiles a filter in the normal form the engine pushes (functionregistered, observeradded). Every rule applies except the encoded size limit, which the engine checked on the filter as written (a normal form can be longer). |
| `IsMatchAll` | `func() bool` | Yes | IsMatchAll reports whether the filter matches every document. |
| `Matches` | func(doc [`Doc`](#doc)) (matched bool) | Yes | Matches evaluates the filter on doc. A nil doc has every root absent. It is total: a host value whose JSON encoding panics reads as no match. |
| `Roots` | func() [`Roots`](#roots) | Yes | Roots reports which roots the filter's clauses read. |
| `Source` | `func() map[string]any` | Yes | Source returns a copy of the filter as decoded JSON (numbers as json.Number). |
