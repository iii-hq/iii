### call

Call a function: resolves to its result.


The routing behavior depends on the `action` field of the request:
- No action: synchronous, waits for the function to return.
- `CallAction::Enqueue`: async via named queue.
- `CallAction::Void`: fire-and-forget.

A function this worker registered itself runs in-process once the
engine allowed it ("local dispatch", see `Dispatch`): same result,
error shape and timeout, and nothing on the wire unless an observer's
filters match the call. A sync handler then runs inline on the
caller's task, where the timeout cannot interrupt it: a sync handler
that can block should be async, or registered with
`RegisterFunction::local_dispatch(false)`.
`CallRequest::dispatch` with `Dispatch::Remote`
forces the engine path. Calls made from inside a handler (or a deliver
hook) carry that handler's invocation as their `caller`.

A request built with `CallRequest::observer` calls through that
observer: the engine runs its target with the payload, as given.


### observe

Observes `source` and calls `target` once per matching call.

`source` is a `Source`, or a function id for every successful call
with the defaults. Returns at once, before the engine answered: the
handle starts `pending`; `ObserverHandle::ready` resolves on
`active` and fails on `error` (`INVALID_ARGS`, `INVALID_FILTER`,
`FORBIDDEN`, `NOT_OBSERVABLE`, an added hook's rejection,
`UNSUPPORTED` against an engine without observe). There is no inline
handler: `target` is a registered function, and the observer stays
`pending` until it is registered.

### engine_supports_observe

Whether the engine on the current connection supports observe: it
advertised `observe.v1` in its `WorkerRegistered`. `None` until that
arrives, before the first connection and again while reconnecting.

Without it, `observe()` fails with `UNSUPPORTED` and the hooks of this
worker's functions never run; a worker can keep a fallback for older
engines when this is `Some(false)`. Pair it with
`on_engine_supports_observe` to
follow changes across reconnects.

**Signature**

```rust
engine_supports_observe() -> Option<bool>
```

#### Example

```rust
if worker.engine_supports_observe() == Some(false) {
    eprintln!("engine without observe: keeping the fallback");
}
```

### observe_with

`observe` with the observer's id, policy and metadata.

An id (`ObserverOptions::id`) that a handle of this client holds,
in any state, is refused at the call: nothing is sent, the holding
handle and its observer are untouched, and the handle returned is in
state `error` with the reason `OBSERVER_ID_CONFLICT`,
`observer id already in use: <id>`. Its `ready`
fails with that code, and its `dispose`
sends nothing.

The id is free again as soon as `dispose()` is called on the handle
that held it, before the engine confirms the disposal. The engine answers a connection's
observes in the order it reads them, so each handle of the id gets the
answers to its own `observe` and `unobserve`: a late `disposed` for
the earlier observer never disposes the new one.

### on_engine_supports_observe

Calls `listener` with the engine's observe support (see
`engine_supports_observe`) when it
becomes known and whenever a later connection's `WorkerRegistered`
changes it (an engine upgraded or rolled back between reconnects).
Not called for a reconnect to an engine that says the same, nor while
reconnecting (the value is unknown then, not changed).

A listener is called with the current value right away when it is
known; one added while it is not (before the first connection,
while reconnecting) hears it from the next `WorkerRegistered`, the
same value or not. Either way it sees every value from the current
one on, in order. Listeners run on the same thread as
`ObserverHandle::on_state_change`
listeners, never on the connection's read loop: one may call the
client.

#### RegisterFunction

Function registration builder.

The function ID is supplied separately at registration time via
`IIIClient::register_function`, `RegisterFunction` only carries the handler
and optional metadata.

Constructors:
- `RegisterFunction::new`: sync function. Accepts both typed handlers
  (schemas auto-extracted via `schemars`) and `Fn(Value, Option<Value>) -> Result<Value, Error>`
  closures. The second argument is the per-invocation metadata sidecar and
  is `None` when absent. A `Value` input or result passes as is; other
  types go through serde.
- `RegisterFunction::new_async`: async equivalent of `new`.
- `RegisterFunction::http`: function invoked over HTTP (Lambda,
  Cloudflare Workers, etc.).

Builder methods (all consume `self`):
- `description`
- `metadata`
- `request_format`: overrides any auto-extracted schema.
- `response_format`: overrides any auto-extracted
  schema; it describes what observers observe.
- `args_format`: the observers' args.
- `private`: only this worker calls it.
- `observable`: `false` refuses every observer.
- `standby`: take over when another host leaves.
- `local_dispatch`: opt out of in-process calls.

The handler's return value is what observers observe. An event source's
handler returns the event it is called with. What the worker does when
the function is observed is set with hooks: see `hooks`.

#### Observer

One observer of a function this worker hosts, as its host sees it: its
id, args, filters, target, capture and `on`. Never its metadata, policy or
observing worker.

Cheap to clone (an `Arc`), so hooks take it by value and a worker keeps it
in its own index. Two `Observer`s are equal when their ids are.

The engine may announce an observer again with the same args and other
filters, target, capture or `on`: it stays the same observer and no hook
runs. Handles given out earlier keep the view they were made with, and
`IIIClient::observers` returns the announced one.

#### Dispatch

Which path `IIIClient::call` takes.

A call to a function registered by this same worker runs in-process
("local dispatch") when all of these hold:

1. the function has a handler here (not `RegisterFunction::http`)
   and was not registered with `RegisterFunction::local_dispatch(false)`;
2. the engine confirmed it with `functionregistered { local_dispatch: true }`;
3. the call resolves to the namespace the function is registered in;
4. the action is not `CallAction::Enqueue` (a `Void` call runs
   locally, fire-and-forget);
5. the dispatch is not `Dispatch::Remote`, and the call is not made
   through an observer (`CallRequest::observer`).

Otherwise the call goes through the engine. A local call returns the same
result, error shape and timeout as a remote one, and is reported to the
engine only when an observer's filters match it.

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `Auto` | `unit` | Yes | Run in-process when the five conditions above hold, else remote. |
| `Remote` | `unit` | Yes | Always route through the engine (engine-side effects, tests). |
