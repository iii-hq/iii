<Info title="Coming from trigger types">
  In 0.26, a trigger type is an observable function: `registerTriggerType` becomes
  `registerFunction` with the hooks on this page, and a consumer's `registerTrigger` becomes
  `observe`. To move a 0.25 worker, see [Upgrading from 0.25.x to 0.26.x](../upgrading/from-0-25-x).
</Info>

Every function your worker registers can be observed unless you specify otherwise (see
[Registration options](#registration-options)). By default, iii runs each observer's target after
each call of the function, with the call's input and the handler's return value. This page is how
your worker changes that: what the observers of its functions receive, which calls reach which
observer, what each observer sets up, and what the caller gets back. To observe a function, see
[Observers](../using-iii/observers).

## Hooks

Your worker defines what observing a function means with four hooks, in two pairs. The observer
lifecycle hooks add your own set-up and teardown per observer. The observation lifecycle hooks
replace how iii matches and delivers calls.

### Observer lifecycle

These hooks run once per observer, when it starts and stops observing the function.

#### `onObserverAdded(obs)`

Runs before the observer is accepted. Use it to set something up from the observer's args. When it
returns, the observer becomes active and receives the function's calls. Throw to reject the observer
instead.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { ObserveRejection } from "iii-sdk";
    import { Pool } from "pg";

    const pools = new Map([["primary", new Pool({ connectionString: process.env.PRIMARY_DATABASE_URL })]]);

    worker.onObserverAdded("database::on-row-changed", async (obs) => {
      const { db, table } = obs.args as { db: string; table: string };
      const pool = pools.get(db);
      if (!pool) throw new ObserveRejection("UNKNOWN_DB", `no database '${db}'`);
      await pool.query(
        `CREATE OR REPLACE TRIGGER iii_${table}_changed AFTER INSERT OR UPDATE OR DELETE ON ${table}
         FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()`,
      );
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    import os

    from iii import ObserveRejection
    from psycopg_pool import ConnectionPool

    pools = {"primary": ConnectionPool(os.environ["PRIMARY_DATABASE_URL"])}

    @worker.on_observer_added("database::on-row-changed")
    def install_trigger(obs):
        db, table = obs.args["db"], obs.args["table"]
        pool = pools.get(db)
        if pool is None:
            raise ObserveRejection("UNKNOWN_DB", f"no database '{db}'")
        with pool.connection() as conn:
            conn.execute(
                f"CREATE OR REPLACE TRIGGER iii_{table}_changed AFTER INSERT OR UPDATE OR DELETE ON {table} "
                "FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()"
            )
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use std::collections::HashMap;
    use std::sync::Arc;

    use iii_sdk::{ObserveRejection, Observer};
    use serde::Deserialize;
    use sqlx::PgPool;

    #[derive(Deserialize)]
    struct RowChangedArgs {
        db: String,
        table: String,
    }

    let pools: Arc<HashMap<String, PgPool>> = Arc::new(HashMap::from([(
        "primary".to_string(),
        PgPool::connect(&std::env::var("PRIMARY_DATABASE_URL")?).await?,
    )]));

    worker.on_observer_added_for("database::on-row-changed", move |obs: Observer| {
        let pools = pools.clone();
        async move {
            let args: RowChangedArgs = obs.args()?;
            let Some(pool) = pools.get(&args.db) else {
                return Err(ObserveRejection::new("UNKNOWN_DB", format!("no database '{}'", args.db)));
            };
            sqlx::query(&format!(
                "CREATE OR REPLACE TRIGGER iii_{0}_changed AFTER INSERT OR UPDATE OR DELETE ON {0} \
                 FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()",
                args.table
            ))
            .execute(pool)
            .await
            .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            Ok(())
        }
    });
    ```

  </Tab>
  <Tab title="Go">
    ```go
    import (
        "database/sql"
        "fmt"
        "os"
    )

    primary, _ := sql.Open("pgx", os.Getenv("PRIMARY_DATABASE_URL"))
    pools := map[string]*sql.DB{"primary": primary}

    type rowChangedArgs struct {
        DB    string `json:"db"`
        Table string `json:"table"`
    }

    worker.OnObserverAddedFor("database::on-row-changed", func(ctx context.Context, obs *iii.Observer) error {
        var args rowChangedArgs
        if err := obs.DecodeArgs(&args); err != nil {
            return err

        pool, ok := pools[args.DB]
        if !ok {
            return iii.ObserveRejection("UNKNOWN_DB", "no database '"+args.DB+"'")
        }
        _, err := pool.ExecContext(ctx, fmt.Sprintf(
            "CREATE OR REPLACE TRIGGER iii_%[1]s_changed AFTER INSERT OR UPDATE OR DELETE ON %[1]s "+
                "FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()", args.Table))
        return err
    })
    ```

#### `onObserverRemoved(obs)`

Runs after the engine has removed the observer and delivery to it has stopped. Use it to perform
your own teardown. An error it throws is logged, and the observer is still removed.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    worker.onObserverRemoved("database::on-row-changed", async (obs) => {
      const { db, table } = obs.args as { db: string; table: string };
      await pools.get(db)?.query(`DROP TRIGGER IF EXISTS iii_${table}_changed ON ${table}`);
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    @worker.on_observer_removed("database::on-row-changed")
    def drop_trigger(obs):
        db, table = obs.args["db"], obs.args["table"]
        pool = pools.get(db)
        if pool is None:
            return
        with pool.connection() as conn:
            conn.execute(f"DROP TRIGGER IF EXISTS iii_{table}_changed ON {table}")
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    let pools = pools.clone();
    worker.on_observer_removed_for("database::on-row-changed", move |obs: Observer| {
        let pools = pools.clone();
        async move {
            let Ok(args) = obs.args::<RowChangedArgs>() else { return };
            if let Some(pool) = pools.get(&args.db) {
                let _ = sqlx::query(&format!("DROP TRIGGER IF EXISTS iii_{0}_changed ON {0}", args.table))
                    .execute(pool)
                    .await;
            }
        }
    });
    ```

  </Tab>
  <Tab title="Go">
    ```go
    worker.OnObserverRemovedFor("database::on-row-changed", func(ctx context.Context, obs *iii.Observer) {
        var args rowChangedArgs
        if obs.DecodeArgs(&args) != nil {
            return
        }
        if pool, ok := pools[args.DB]; ok {
            pool.ExecContext(ctx, fmt.Sprintf("DROP TRIGGER IF EXISTS iii_%[1]s_changed ON %[1]s", args.Table))
        }
    })
    ```

### Observation lifecycle

These hooks run per call. An observation is one call of the function reaching, or being considered
for, one observer.

#### `onObservationMatch(obs, call)`

By default, every call is observed by every observer. Override it to select, for one call, which
observers get it, from their args: a predicate, or keys that iii indexes.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    worker.onObservationMatch(
      "database::on-row-changed",
      (obs, call) => obs.args.db === call.input.db && obs.args.table === call.input.table,
    );
    ```

  </Tab>
  <Tab title="Python">
    ```python
    worker.on_observation_match(
        "database::on-row-changed",
        lambda obs, call: obs.args["db"] == call.input["db"] and obs.args["table"] == call.input["table"],
    )
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::Match;

    worker.on_observation_match_for(
        "database::on-row-changed",
        Match::predicate(|obs, call| {
            let args = obs.args_value();
            args["db"] == call.input["db"] && args["table"] == call.input["table"]
        }),
    );
    ```

  </Tab>
  <Tab title="Go">
    ```go
    type rowChange struct {
        DB    string `json:"db"`
        Table string `json:"table"`
    }

    worker.OnObservationMatchFor("database::on-row-changed", iii.MatchFunc(func(obs *iii.Observer, call *iii.Call) bool {
        var change rowChange
        _ = json.Unmarshal(call.Input, &change)
        return obs.Args["db"] == change.DB && obs.Args["table"] == change.Table
    }))
    ```

  </Tab>
</Tabs>

#### `onObservationDeliver(call, observers)`

By default, iii carries out each observation: it runs the target of every matched observer whose
`on` and filters match the call, and gives the caller the handler's return value. Override it to
deliver the call yourself and return what the caller gets back.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    type HttpRequest = { method: string; path: string };

    worker.onObservationDeliver("http::on-request", async (call, observers) => {
      const request = call.input as HttpRequest;
      const route = observers.find(
        (obs) => obs.args.method === request.method && obs.args.path === request.path,
      );
      if (!route) return { status_code: 404 };
      if (!route.matches(call)) return { status_code: 422 }; // the observer's `on` and filters
      return worker.call({ observer: route, payload: request });
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    @worker.on_observation_deliver("http::on-request")
    async def deliver(call, observers):
        request = call.input
        route = next(
            (obs for obs in observers
             if obs.args["method"] == request["method"] and obs.args["path"] == request["path"]),
            None,
        )
        if route is None:
            return {"status_code": 404}
        if not route.matches(call):
            return {"status_code": 422}  # the observer's `on` and filters
        return await worker.call_async({"observer": route, "payload": request})
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::protocol::CallRequest;
    use iii_sdk::{Call, Observer};
    use serde_json::json;

    let client = worker.clone();
    worker.on_observation_deliver_for("http::on-request", move |call: Call, observers: Vec<Observer>| {
        let worker = client.clone();
        async move {
            let route = observers.into_iter().find(|obs| {
                let args = obs.args_value();
                args["method"] == call.input["method"] && args["path"] == call.input["path"]
            });
            let Some(route) = route else {
                return Ok(json!({ "status_code": 404 }));
            };
            if !route.matches(&call) {
                return Ok(json!({ "status_code": 422 })); // the observer's `on` and filters
            }
            worker.call(CallRequest::observer(&route, call.input)).await
        }
    });
    ```

  </Tab>
  <Tab title="Go">
    ```go
    type httpRequest struct {
        Method string `json:"method"`
        Path   string `json:"path"`
    }

    worker.OnObservationDeliverFor("http::on-request", func(ctx context.Context, call *iii.Call, observers []*iii.Observer) (any, error) {
        var request httpRequest
        if err := json.Unmarshal(call.Input, &request); err != nil {
            return nil, err
        }
        for _, obs := range observers {
            if obs.Args["method"] == request.Method && obs.Args["path"] == request.Path {
                if !obs.Matches(call) {
                    return map[string]int{"status_code": 422}, nil // the observer's `on` and filters
                }
                return worker.Call(ctx, iii.CallRequest{Observer: obs, Payload: call.Input})
            }
        }
        return map[string]int{"status_code": 404}, nil
    })
    ```

  </Tab>
</Tabs>

## Publish events

An event source is a function whose handler returns the event. The worker calls it each time the
event happens, and each call runs the function's observers. `private: true` keeps the calls to this
worker: other workers can observe the function, and only this worker can call it (see
[Private functions](#private-functions)).

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    type FileChanged = { path: string; event: "created" | "modified" | "deleted" };

    worker.registerFunction("files::on-change", (change: FileChanged) => change, { private: true });

    // whenever a file changes:
    await worker.call({ function_id: "files::on-change", payload: change });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    worker.register_function("files::on-change", lambda change: change, private=True)

    # whenever a file changes:
    worker.call({"function_id": "files::on-change", "payload": {"path": path, "event": "modified"}})
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::protocol::CallRequest;
    use iii_sdk::{Error, RegisterFunction};
    use schemars::JsonSchema; // schemars 0.8, the version iii-sdk uses
    use serde::{Deserialize, Serialize};
    use serde_json::json;

    #[derive(Serialize, Deserialize, JsonSchema)]
    struct FileChanged {
        path: String,
        event: String,
    }

    worker.register_function(
        "files::on-change",
        RegisterFunction::new(|change: FileChanged| Ok::<_, Error>(change)).private(),
    );

    // whenever a file changes:
    let change = json!({ "path": path, "event": "modified" });
    worker.call(CallRequest::new("files::on-change", change)).await?;
    ```

  </Tab>
  <Tab title="Go">
    ```go
    // iii.Identity returns the event it is called with.
    worker.RegisterFunction("files::on-change", iii.Identity, iii.FunctionOptions{Private: true})

    // whenever a file changes:
    change, _ := json.Marshal(map[string]string{"path": path, "event": "modified"})
    worker.Call(ctx, iii.CallRequest{FunctionID: "files::on-change", Payload: change})
    ```

  </Tab>
</Tabs>

A consumer observes it like any other function:

```typescript
worker.observe(
  {
    function_id: "files::on-change",
    filters: { "input.path": { $prefix: "/data/" } },
    deliver: "input",
  },
  "csv::process",
);
```

## Know when a function is observed

`FunctionRef.isObserved()` returns true when the function has at least 1 active observer. It costs
one atomic load, so call it before you build an event, and skip the event when the function has no
observers.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    const prices = worker.registerFunction(
      "prices::on-change",
      (change: PriceChange) => change,
      { private: true },
    );

    // called for every tick of the price feed
    async function publishPrice(tick: Tick) {
      if (!prices.isObserved()) return; // no observers: skip building the event

      const change = toPriceChange(tick);
      await worker.call({ function_id: "prices::on-change", payload: change });
    }
    ```

  </Tab>
  <Tab title="Python">
    ```python
    prices = worker.register_function("prices::on-change", lambda change: change, private=True)

    # called for every tick of the price feed
    def publish_price(tick):
        if not prices.is_observed():
            return  # no observers: skip building the event

        change = to_price_change(tick)
        worker.call({"function_id": "prices::on-change", "payload": change})
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    let prices = worker.register_function(
        "prices::on-change",
        RegisterFunction::new(|change: PriceChange| Ok::<_, Error>(change)).private(),
    );

        if !prices.is_observed() {

        }

        let change = to_price_change(&tick);
        worker.call(CallRequest::new("prices::on-change", json!(change))).await?;
        Ok(())
    }
    ```

  </Tab>
  <Tab title="Go">
    ```go

            return nil // no observers: skip building the event
    ```

Because the worker calls its own function, the call runs in-process
([local dispatch](../using-iii/observers#local-dispatch)) and reaches the engine only when an
observer's filters match. On a function whose observers are
[matched by keys](#match-observers-to-calls), `isObserved(call)` also answers whether one particular
call would reach an observer.

## Set up and tear down per observer

`onObserverAdded` and `onObserverRemoved` can be set for one function, or for every function the
worker hosts, and both levels run:

- When an observer is added, the worker's `onObserverAdded` runs, then the function's.
- When an observer is removed, the function's `onObserverRemoved` runs, then the worker's.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { Client } from "pg";

    // every function this worker hosts: hold one LISTEN connection while anything is observed
    let listener: Client | undefined;
    let observed = 0;

    worker.onObserverAdded(async () => {
      if (observed++ > 0) return;
      listener = new Client({ connectionString: process.env.PRIMARY_DATABASE_URL });
      await listener.connect();
      await listener.query("LISTEN iii_row_changed");
    });

    worker.onObserverRemoved(async () => {
      if (--observed > 0) return;
      await listener?.end();
      listener = undefined;
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    import os

    import psycopg

    # every function this worker hosts: hold one LISTEN connection while anything is observed
    listener: psycopg.Connection | None = None
    observed = 0

    @worker.on_observer_added
    def open_listener(obs):
        global listener, observed
        observed += 1
        if observed > 1:
            return
        listener = psycopg.connect(os.environ["PRIMARY_DATABASE_URL"], autocommit=True)
        listener.execute("LISTEN iii_row_changed")

    @worker.on_observer_removed
    def close_listener(obs):
        global listener, observed
        observed -= 1
        if observed > 0:
            return
        listener.close()
        listener = None
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use std::sync::atomic::{AtomicUsize, Ordering};
    use std::sync::Arc;

    use iii_sdk::{ObserveRejection, Observer};
    use sqlx::postgres::PgListener;
    use tokio::sync::Mutex;

    // every function this worker hosts: hold one LISTEN connection while anything is observed
    let listener: Arc<Mutex<Option<PgListener>>> = Arc::new(Mutex::new(None));
    let observed = Arc::new(AtomicUsize::new(0));

    let (slot, count) = (listener.clone(), observed.clone());
    worker.on_observer_added(move |_obs: Observer| {
        let (slot, count) = (slot.clone(), count.clone());
        async move {
            if count.fetch_add(1, Ordering::SeqCst) > 0 {
                return Ok(());
            }
            let url = std::env::var("PRIMARY_DATABASE_URL").unwrap_or_default();
            let mut conn = PgListener::connect(&url)
                .await
                .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            conn.listen("iii_row_changed")
                .await
                .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            *slot.lock().await = Some(conn);
            Ok(())
        }
    });

    let (slot, count) = (listener.clone(), observed.clone());
    worker.on_observer_removed(move |_obs: Observer| {
        let (slot, count) = (slot.clone(), count.clone());
        async move {
            if count.fetch_sub(1, Ordering::SeqCst) > 1 {
                return;
            }
            slot.lock().await.take();
        }
    });
    ```

  </Tab>
  <Tab title="Go">
    ```go
    import (
        "os"
        "sync"

        "github.com/jackc/pgx/v5"
    )

        listener *pgx.Conn
        observed int
    )

    worker.OnObserverAdded(func(ctx context.Context, obs *iii.Observer) error {
        mu.Lock()
        defer mu.Unlock()
        observed++
        if observed > 1 {
            return nil
        }
        conn, err := pgx.Connect(ctx, os.Getenv("PRIMARY_DATABASE_URL"))
        if err != nil {
            return err
        }
        if _, err := conn.Exec(ctx, "LISTEN iii_row_changed"); err != nil {
            return err
        }
        listener = conn
        return nil
    })

    worker.OnObserverRemoved(func(ctx context.Context, obs *iii.Observer) {
        mu.Lock()
        defer mu.Unlock()
        observed--
        if observed > 0 {
            return
        }
        listener.Close(ctx)
        listener = nil
    })
    ```

  </Tab>

A hook for one function is set by id (see [Hooks](#hooks)) or chained on the `FunctionRef` that
`registerFunction` returns. Each method returns its receiver, so calls chain. Added, removed and
deliver hooks can be sync or async. A match predicate and key functions are sync, since they run on
every call.

Pass `null` to remove a hook: iii's default behaviour returns (see [Hooks](#hooks)).

Hooks are stored by function id. They stay in place across `unregister()` and a later registration
of the same id, and they can be set before the function is registered. Once the worker's connection
is registered, the SDK logs a warning for each hook id the worker has not registered, which catches
a mistyped id.

### Accept or reject an observer

- **Accepted.** An observer is accepted when every `onObserverAdded` that applies to it has
  resolved. The SDK then acknowledges it to the engine, and the observer becomes `active`. So its
  database trigger exists before the first call it must receive.
- **Rejected.** When an `onObserverAdded` throws, the observer is rejected. A thrown
  `ObserveRejection(code, message)` sets the code the consumer's `ready()` fails with; any other
  error is `OBSERVE_REJECTED`. The `onObserverRemoved` of each level whose `onObserverAdded` already
  resolved runs, so a worker-wide hook that retained a resource releases it.
- **Removed.** `onObserverRemoved` runs exactly once for every accepted observer: when the consumer
  disposes it, when `max_fires` or expiry ends it, when the observing worker disconnects, and on a
  late rejection with `obs.reject()`. For an observer that is never accepted, it runs only at the
  levels whose `onObserverAdded` resolved. No SDK runs it yet when the worker that hosts the
  function shuts down.
- **Away and back.** When the observing worker disconnects, its observers are `suspended` for
  `observers.observer_grace_ms` (30 s by default), and the worker that hosts the function runs
  `onObserverRemoved` for each. If the observing worker reconnects in that time, the host gets each
  observer again, in the order they were created, runs `onObserverAdded`, and the observer is
  `active` once it is accepted.
- **Back on a new connection.** A restarted observing worker observes under the ids it used before.
  Under the same worker name, namespace and principal, its observe replaces the `suspended` observer
  (see [Observer states](../using-iii/observers#observer-states)); from any other worker the id
  stays taken (`OBSERVER_ID_CONFLICT`) until the grace period ends. The host already ran
  `onObserverRemoved` for the old observer and receives nothing more about it. It gets the new
  observer like any other and runs `onObserverAdded`, so a resource kept by `obs.id`, such as a
  queue subscriber's backlog, serves the new observer.
- **One at a time.** For each function, the SDK runs observer lifecycle hooks one at a time, in the
  order the engine announced the observers. Hooks of different functions run concurrently.
- **Timeout.** An `onObserverAdded` that runs past 30 seconds (`observers.owner_ack_timeout_ms` in
  the engine) fails the observer with `OWNER_TIMEOUT`. A removed hook that runs past it is logged.

### When hooks take effect

The SDK acknowledges no observer of a function before the call that registered the function has
returned. So set hooks by id before `registerFunction`: they run for every observer. In Node, a hook
chained on the `registerFunction` result, or set later in the same synchronous block, runs for every
observer too, since inbound messages run on the event loop.

A hook set once a function already has active observers is caught up: the SDK runs it for each of
them at once, a throw late-rejects that observer, and the SDK logs one warning naming the function
and the number of observers that were active without the hook. Replacing a hook while observers are
active behaves differently across SDKs, so set each hook once.

### Reject an observer later

An observer that the function accepted can become invalid later. For example, a configuration reload
can remove the resource that the observer watches. `obs.reject(code, message)` stops delivery to the
observer immediately, and the SDK runs `onObserverRemoved` next, connected or not. The engine moves
the observer to `error` with that code. If the connection is lost, the SDK sends the rejection again
after it reconnects.

```typescript
for (const obs of feeds.observers()) {
  if (!config.sources.includes(obs.args.source as string)) {
    obs.reject("UNKNOWN_SOURCE", `source ${obs.args.source} was removed`);
  }
}
```

`FunctionRef.observers()` returns the active observers of the function.

## Choose who gets each call

Every call of a function, local or routed, runs in the worker that hosts the function, in three
steps:

1. **The handler runs.** Its return value is what observers observe.
2. **The call's observations are decided.** An observation is the call reaching one observer. By
   default every observer of the function gets every call.
   [`onObservationMatch`](#match-observers-to-calls) narrows that.
3. **The observations are carried out.** By default iii delivers the call to each observer.
   [`onObservationDeliver`](#deliver-calls-yourself) takes delivery over.

iii's delivery:

1. selects, among the matching observers, those whose `on` matches the call's status and whose
   filters match the call. The engine does it for a call it routed to the worker, with the input it
   forwarded and the result the worker answers; the worker does it for a call it makes to its own
   function;
2. runs each target with the observer's `deliver` choice, policy, metadata, and
   [loop guard](../using-iii/observers#loop-guard);
3. gives the caller the handler's return value, or rethrows its error.

It does not wait for targets. The caller and the observers receive the same value. The engine finds
the observers whose filters hold an `$eq` or `$in` on a value of the call through an index, so a
routed call costs about one lookup however many observers filter on their own value (see
[Filters](../reference/filters#many-observers)).

### Match observers to calls

`onObservationMatch` selects, for each call, which observers get it. A function sets it when its
observers' args determine which calls they get. iii does everything else as usual: each observer's
`on`, filters, policy and `deliver` still apply.

As a predicate, the hook takes one possible observation, the observer and the call, and returns
whether it happens.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    worker.onObservationMatch(
      "database::on-row-changed",
      (obs, call) => obs.args.db === call.input.db && obs.args.table === call.input.table,
    );
    ```

  </Tab>
  <Tab title="Python">
    ```python
    worker.on_observation_match(
        "database::on-row-changed",
        lambda obs, call: obs.args["db"] == call.input["db"] and obs.args["table"] == call.input["table"],
    )
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::Match;

    worker.on_observation_match_for(
        "database::on-row-changed",
        Match::predicate(|obs, call| {
            let args = obs.args_value();
            args["db"] == call.input["db"] && args["table"] == call.input["table"]
        }),
    );
    ```

  </Tab>
  <Tab title="Go">
    ```go
    worker.OnObservationMatchFor("database::on-row-changed", iii.MatchFunc(func(obs *iii.Observer, call *iii.Call) bool {
        var change rowChange
        _ = json.Unmarshal(call.Input, &change)
        return obs.Args["db"] == change.DB && obs.Args["table"] == change.Table
    }))
    ```

  </Tab>
</Tabs>

The SDK calls the predicate once per observation: for every call, once for each active observer,
before that observer's `on` and filters. A predicate that throws counts as no match for that
observer, and the SDK logs it once per function.

Keys suit a function with many observers. One key function gives the keys an observer listens for,
the other gives the keys a call is, and an observer matches a call when they share a key. The SDK
keeps an index from keys to observers, so a call costs one lookup per key.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    worker.onObservationMatch("prices::on-change", {
      observer: (obs) => obs.args.symbol as string, // the keys this observer listens for
      call: (call) => call.input.symbol, // the keys this call is
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    worker.on_observation_match(
        "prices::on-change",
        observer=lambda obs: obs.args["symbol"],  # the keys this observer listens for
        call=lambda call: call.input["symbol"],  # the keys this call is
    )
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::{Keys, Match};

    worker.on_observation_match_for(
        "prices::on-change",
        Match::keys(
            // the keys this observer listens for
            |obs| Keys::from(obs.args_value()["symbol"].as_str()),
            // the keys this call is
            |call| Keys::from(call.input["symbol"].as_str()),
        ),
    );
    ```

  </Tab>
  <Tab title="Go">
    ```go
    worker.OnObservationMatchFor("prices::on-change", iii.MatchKeys(
        // the keys this observer listens for
        func(obs *iii.Observer) []string {
            symbol, _ := obs.Args["symbol"].(string)
            return []string{symbol}
        },
        // the keys this call is
        func(call *iii.Call) []string {
            var change struct {
                Symbol string `json:"symbol"`
            }
            _ = json.Unmarshal(call.Input, &change)
            return []string{change.Symbol}
        },
    ))
    ```

  </Tab>
</Tabs>

- Each key function returns a string or an array of strings.
- The SDK computes an observer's keys once, when it is accepted, and files the observer under each.
  It unfiles the observer when it is removed. An observer whose key function throws is rejected with
  `OBSERVE_REJECTED`.
- The SDK computes a call's keys once per call. A call matches the observers filed under any of its
  keys, each once.
- A match hook set while the function has active observers rebuilds the index from them.

Keys express wildcards by listing them. The
[database worker](./database#how-the-worker-hosts-row-changes) files an observer of every table
under `"primary|*|insert"`, and gives a change the keys `"primary|orders|insert"`,
`"primary|orders|*"`, `"primary|*|insert"` and `"primary|*|*"`: four lookups, whatever the number of
observers. Keys suit sources whose observers each get a slice of many calls.

`isObserved(call)` is true when an observer is filed under one of the call's keys: one hash lookup
per key. A source uses it to skip building an event that no observer gets. On a function without
keys, the call is ignored.

### Deliver calls yourself

`onObservationDeliver` carries out a call's observations: it hands the call to its observers and
returns their answer to the caller. It is for a function whose observers' answers matter, or whose
calls each go to one observer. The hook receives the call and the observers that matched it (by
`onObservationMatch`, or every active observer), as a snapshot taken when the call started. What it
returns (or throws) is what the caller gets back; iii delivers nothing for that function. The hook
runs inside the function's invocation, so calls it makes have that invocation as their caller.

Choose observers in `onObservationMatch` when an observer's args and the call settle it. Choose them
in `onObservationDeliver` when choosing compares observers with each other or produces part of the
payload. An HTTP request goes to the most specific of the route patterns that fit its path, and that
route's path parameters go into the request its target receives, so `http::on-request` sets no match
hook and its deliver hook receives every active observer.

The hook applies each observer's `on` and filters with `obs.matches(call)` and runs its target with
a [call through the observer](#call-through-an-observer). With both hooks set, the deliver hook
receives only the observers the match hook matched:
[`queue::on-message`](./queues#how-the-worker-hosts-messages) files each message under its
subscriber's key, so its deliver hook receives that one observer.

### Call through an observer

A call that names an observer runs that observer's target and resolves to the target's result:

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { CallAction } from "iii-sdk";

    const result = await worker.call({ observer: obs, payload }); // the target's result
    await worker.call({ observer: obs, payload, action: CallAction.Void() }); // fire-and-forget
    ```

  </Tab>
  <Tab title="Python">
    ```python
    from iii import CallAction

    result = await worker.call_async({"observer": obs, "payload": payload})  # the target's result
    await worker.call_async({"observer": obs, "payload": payload, "action": CallAction.Void()})  # fire-and-forget
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::{CallAction, CallRequest};

    let result = worker.call(CallRequest::observer(&obs, payload.clone())).await?; // the target's result
    worker.call(CallRequest::observer(&obs, payload).action(CallAction::Void)).await?; // fire-and-forget
    ```

  </Tab>
  <Tab title="Go">
    ```go
    result, err := worker.Call(ctx, iii.CallRequest{Observer: obs, Payload: payload}) // the target's result
    worker.Call(ctx, iii.CallRequest{Observer: obs, Payload: payload, Action: iii.VoidAction()}) // fire-and-forget
    ```

  </Tab>
</Tabs>

- Only the worker that hosts the observer's function may call through it.
- The engine checks that the observer exists, that the caller hosts its function, and that the
  observer is active. Then it routes the call to the observer's stored target and applies the
  observer's policy (`max_fires`, expiry, `max_in_flight`), metadata, and loop guard, as for iii's
  delivery.
- The call takes no metadata. The target's metadata argument is the observer's registration
  metadata, as on iii's delivery. `call` refuses a call through an observer that names metadata
  before sending anything, with the error "a call through an observer takes no metadata; its target
  receives the observer's metadata". `null` is no metadata. Put anything the target needs from the
  call in the payload.
- The host calls through an observer wherever it needs to once the observer is active: in the
  function's deliver hook, or to
  [send one observer its initial state](#send-an-observer-its-initial-state).

A call through an observer fails with the target's own error, or with one of these codes:

| Code                  | When                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `NOT_FUNCTION_OWNER`  | This worker does not host the observer's function.                                                                     |
| `OBSERVER_NOT_FOUND`  | The engine has no observer with this id.                                                                               |
| `OBSERVER_NOT_ACTIVE` | The observer is not active yet (for example, inside `onObserverAdded`), or it was removed or rejected before the call. |
| `LOOP_GUARD`          | The call is deeper than `observers.max_observe_depth`.                                                                 |
| `OVERFLOW`            | The observer has `max_in_flight` calls running.                                                                        |
| `TIMEOUT`             | The target did not answer within `observers.activation_timeout_ms` (30 s by default).                                  |

A target that goes away suspends the observer, so a call through it fails with `OBSERVER_NOT_ACTIVE`
until the target is registered again. A fire-and-forget call that the engine refuses is dropped and
counted as a drop under its code, with a `debug` log.

### Send an observer its initial state

A source sends one observer something of its own, such as its current state when the observer is
added or an event it missed, by [calling through that observer](#call-through-an-observer). The call
runs that observer's target and no other.

`obs.accepted()` resolves once the SDK has acknowledged the observer. A call made after it resolves
reaches an active observer, since the engine handles a connection's messages in order, as long as
the observer's target is registered: an observer whose target is not registered yet stays `pending`,
and the call fails with `OBSERVER_NOT_ACTIVE`. The observer becomes active after its
`onObserverAdded` returns, so the hook starts a task that waits for `accepted()` and then makes the
call. `accepted()` fails for an observer rejected first, such as one whose match key function
throws, and the task then sends nothing.

The target receives the payload as given, with the observer's registration metadata. Send what your
function's targets expect.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { CallAction } from "iii-sdk";

    worker.onObserverAdded("tmux::on-changed", (obs) => {
      // send the session's current state once the observer is active
      void obs
        .accepted()
        .then(() =>
          worker.call({
            observer: obs,
            payload: sessions.state(obs.args.session as string),
            action: CallAction.Void(),
          }),
        )
        .catch(() => {
          // a rejected observer gets nothing
        });
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    import asyncio

    from iii import CallAction, ObserveRejection

    async def send_state(obs):
        try:
            await obs.accepted_async()
        except ObserveRejection:
            return  # a rejected observer gets nothing
        await worker.call_async({
            "observer": obs,
            "payload": sessions.state(obs.args["session"]),
            "action": CallAction.Void(),
        })

    @worker.on_observer_added("tmux::on-changed")
    async def on_added(obs):
        # send the session's current state once the observer is active
        asyncio.create_task(send_state(obs))
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::{CallAction, CallRequest, Observer};

    let iii = worker.clone();
    worker.on_observer_added_for("tmux::on-changed", move |obs: Observer| {
        let iii = iii.clone();
        async move {
            // send the session's current state once the observer is active
            tokio::spawn(async move {
                if obs.accepted().await.is_ok() {
                    let request = CallRequest::observer(&obs, session_state(obs.args_value()));
                    let _ = iii.call(request.action(CallAction::Void)).await;
                }
            });
            Ok(())
        }
    });
    ```

  </Tab>
  <Tab title="Go">
    ```go
    worker.OnObserverAddedFor("tmux::on-changed", func(ctx context.Context, obs *iii.Observer) error {
        // send the session's current state once the observer is active
        go func() {
            if obs.Accepted(context.Background()) != nil {
                return
            }
            worker.Call(context.Background(), iii.CallRequest{
                Observer: obs,
                Payload:  sessions.State(obs.Args["session"]),
                Action:   iii.VoidAction(),
            })
        }()
        return nil
    })
    ```

  </Tab>
</Tabs>

## Registration options

These options of `registerFunction` describe the function to the engine:

| Option                    | Default | Meaning                                                                                                                             |
| ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `description`, `metadata` | none    | Shown in discovery and the console.                                                                                                 |
| `request_format`          | none    | The JSON Schema of the call's input.                                                                                                |
| `response_format`         | none    | The JSON Schema of the handler's return value: what observers observe.                                                              |
| `args_format`             | none    | The JSON Schema of observers' `args`. The engine validates `args` against it (`INVALID_ARGS`). A function without it takes no args. |
| `private`                 | `false` | Only this worker may call the function. Other workers may observe it. See [Private functions](#private-functions).                  |
| `observable`              | `true`  | `false`: no worker may observe the function (`NOT_OBSERVABLE`).                                                                     |

An `args_format` that is not a valid JSON Schema fails the registration with `INVALID_ARGS_FORMAT`.

### Private functions

An event source is observed by everyone and called only by its own worker. A call from another
worker would be a forged request or row change carrying the source's identity. `private: true`
expresses that:

- The engine accepts a call of a private function only from the connection that hosts it. Any other
  connection, and the engine itself, gets `FORBIDDEN`. A call through an observer is the observing
  worker's call, and an activation is the engine's.
- A private function is observable, and its observers receive every call its worker makes.
- A private function cannot be an observer's target (`FORBIDDEN` at `observe`).
- A worker's call to its own private function passes the input and the result by reference. No other
  worker can read either value, so the SDK copies neither, and the handler and hooks treat both as
  read-only. With `NODE_ENV=development`, the Node SDK freezes them, so a write throws. An
  observer's target receives its own copy, serialized when the call matches.

Any function can be private; event sources are the common case.

### Functions no worker may observe

Some functions must stay unobserved, for example because their input carries credentials. Register
them with `observable: false`. Every `observe` of them fails with `NOT_OBSERVABLE`.

### One host per function

A function id has one host per namespace: the engine rejects a second registration of the same id
with `FUNCTION_NAMESPACE_CONFLICT`. Observer hooks therefore run once per observer, in that host,
and a database trigger is set up once however many instances of the worker run.

A second instance refused with `FUNCTION_NAMESPACE_CONFLICT` logs it and keeps serving its other
functions. It does not register the function again. When the host disconnects, the function's
observers go `pending`, and the next worker that registers the function (the host restarted, or
another instance) receives the current observers, runs its hooks for each, and they become active
again.

Run one instance of a worker that hosts an event source, and let the platform that runs it restart
it. Stop the old instance before the new one starts (`strategy: Recreate` in Kubernetes): an
instance started while the old one runs is refused the function, and nothing hosts it once the old
one stops. The engine also admits one live worker per worker name and namespace: an instance under
the host's name is refused with `WORKER_NAMESPACE_CONFLICT`, and its SDK stops without reconnecting.

## The `Observer` object

Hooks get an `Observer`: the record of what the consumer asked for. Who observes, the observer's
metadata and its policy stay with the engine. The object stays the same for the full life of the
observer, so the worker can keep it, for example in a map.

| Member                  | Meaning                                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | The observer id.                                                                                                                    |
| `function_id`           | The observed function.                                                                                                              |
| `args`                  | The observer's args, already validated against `args_format` by the engine.                                                         |
| `filters`               | The observer's filters in [normal form](../reference/filters#normal-form).                                                          |
| `target`                | The target function id.                                                                                                             |
| `on`, `capture`         | Which calls the observer gets (`success`, `error` or `complete`), and which parts of the call its envelope carries.                 |
| `matches(call)`         | Evaluates the observer's `on` and filters on a call.                                                                                |
| `accepted()`            | Resolves once the SDK has acknowledged the observer. See [Send an observer its initial state](#send-an-observer-its-initial-state). |
| `reject(code, message)` | Late rejection of an active observer. See [Reject an observer later](#reject-an-observer-later).                                    |

To reject an observer from `onObserverAdded`, throw `new ObserveRejection(code, message)`.

## The `Call` object

`onObservationMatch` and `onObservationDeliver` receive the call:

| Field           | Meaning                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------- |
| `function_id`   | The function that was called.                                                               |
| `invocation_id` | The id of the call.                                                                         |
| `status`        | `success` or `error`.                                                                       |
| `input`         | The call's input.                                                                           |
| `output`        | The handler's return value: what observers observe.                                         |
| `error`         | `{ code, message }`, what the handler threw.                                                |
| `caller`        | Who made the call. See [Caller and causality](../using-iii/observers#caller-and-causality). |
| `metadata`      | The call's metadata.                                                                        |
