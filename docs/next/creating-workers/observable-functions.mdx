<Info title="Coming from trigger types">
  In 0.26, a trigger type is an observable function: `registerTriggerType` becomes
  `registerFunction` with the hooks on this page. To move a 0.25 worker, see [Upgrading from 0.25.x
  to 0.26.x](../upgrading/from-0-25-x).
</Info>

Every function your worker registers can be observed unless you specify otherwise (see
[Registration options](#registration-options)). By default, iii runs each observer's target after
each successful call of the function, with what the observer captures: the call's input, the
handler's return value, the caller and the call's metadata unless its `capture` says otherwise (see
[Observers](../using-iii/observers)). This page describes
how to manage this: what the observers of its functions receive, which calls reach which observer,
what each observer sets up, and what the caller gets back. To observe a function, see
[Observers](../using-iii/observers).

## Hooks

Your worker defines function observation with four hooks, two are observer specific, and two are
specific to each individual observation. Every hook is optional. Without it, iii's default applies;
setting it overrides that default for the function, or, set at the worker level, for every function
the worker hosts.

| Hook                   | Default, without the hook                                                            | Setting the hook overrides it                                                            |
| ---------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `onObserverAdded`      | Every observer is accepted as soon as it is added.                                   | Your set-up runs first; the observer is accepted when it returns, rejected if it throws. |
| `onObserverRemoved`    | Nothing runs.                                                                        | Your teardown runs.                                                                      |
| `onObservationMatch`   | Every call is observed by every observer.                                            | Your hook selects which observers get each call.                                         |
| `onObservationDeliver` | iii runs each matched observer's target; the caller gets the handler's return value. | You deliver the call yourself and decide what the caller gets back.                      |

Each observer's `capture` and filters still decide what its target receives, whichever hooks are
set, unless `onObservationDeliver` runs the targets itself.

Both observer lifecycle hooks can be set for one function or for every function the worker hosts,
and both levels run. When an observer is added, the worker's hook runs, then the function's. When an
observer is removed, the function's hook runs, then the worker's. For each function the SDK runs the
observer lifecycle hooks one at a time, in the order the engine announced the observers; hooks of
different functions run concurrently.

### Observer lifecycle

These hooks run once per observer, when it starts and stops observing the function.

#### `onObserverAdded(obs)`

By default, every observer is accepted as soon as it is added. Setting this hook overrides that: it
runs before the observer is accepted. Use it to set something up from the observer's args. When it
returns, the observer becomes active and receives the function's calls. Throw to reject the observer
instead. A hook that runs past 30 seconds (`observers.owner_ack_timeout_ms`) fails the observer with
`OWNER_TIMEOUT`; a removed hook that runs past it is only logged.

  <Tab title="Node / TypeScript">
    ```typescript
    import { ObserveRejection } from "iii-sdk";
    import { Pool } from "pg";

    const pools = new Map([["primary", new Pool({ connectionString: process.env.PRIMARY_DATABASE_URL })]]);

    worker.onObserverAdded("database::on-row-changed", async (obs) => {
      const { db, table } = obs.args as { db: string; table: string };
      const pool = pools.get(db);
      if (!pool) throw new ObserveRejection("UNKNOWN_DB", `no database '${db}'`);
      await pool.query(
        `CREATE OR REPLACE TRIGGER iii_${table}_changed AFTER INSERT OR UPDATE OR DELETE ON ${table}
         FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()`,
      );
    });
    ```

    ```rust
    use std::sync::Arc;

    use iii_sdk::{ObserveRejection, Observer};
    use serde::Deserialize;
    use sqlx::PgPool;

    #[derive(Deserialize)]

        db: String,
        table: String,

        let pools = pools.clone();

            let args: RowChangedArgs = obs.args()?;
            let Some(pool) = pools.get(&args.db) else {
                return Err(ObserveRejection::new("UNKNOWN_DB", format!("no database '{}'", args.db)));
            };
            sqlx::query(&format!(

                 FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()",
                args.table
            ))
            .execute(pool)
            .await
            .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            Ok(())
        }
    });
    ```

    ```go
    import (
        "context"

        "fmt"
        "os"

        pool, ok := pools[args.DB]
        if !ok {
            return iii.ObserveRejection("UNKNOWN_DB", "no database '"+args.DB+"'")

        _, err := pool.ExecContext(ctx, fmt.Sprintf(
            "CREATE OR REPLACE TRIGGER iii_%[1]s_changed AFTER INSERT OR UPDATE OR DELETE ON %[1]s "+
                "FOR EACH ROW EXECUTE FUNCTION iii_notify_row_changed()", args.Table))
        return err
    })
    ```

#### `onObserverRemoved(obs)`

Runs after the engine has removed the observer and delivery to it has stopped. Use it to perform
your own teardown. It runs once for each accepted observer, when the consumer disposes it, when
`max_fires` or expiry ends it, when the observing worker disconnects, and after a late rejection.
For an observer that is never accepted it runs only at the levels whose `onObserverAdded` resolved.

<Note>
  If `onObserverRemoved` throws an error it will cause the error to be logged but it will not
  prevent observer removal. Observer removal happens at the engine level.
</Note>

    ```typescript
      const { db, table } = obs.args as { db: string; table: string };
    ```

#### Set a hook for one function or for every function

A hook set on the worker runs for every function the worker hosts. A hook set on one function runs
for that function only.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { Client } from "pg";

    // every function this worker hosts: hold one LISTEN connection while anything is observed
    let listener: Client | undefined;
    let observed = 0;

    worker.onObserverAdded(async () => {
      if (observed++ > 0) return;
      listener = new Client({ connectionString: process.env.PRIMARY_DATABASE_URL });
      await listener.connect();
      await listener.query("LISTEN iii_row_changed");
    });

    worker.onObserverRemoved(async () => {
      if (--observed > 0) return;
      await listener?.end();
      listener = undefined;
    });
    ```

    ```rust
    use std::sync::atomic::{AtomicUsize, Ordering};
    use std::sync::Arc;

    use iii_sdk::{ObserveRejection, Observer};
    use sqlx::postgres::PgListener;
    use tokio::sync::Mutex;

    // every function this worker hosts: hold one LISTEN connection while anything is observed
    let listener: Arc<Mutex<Option<PgListener>>> = Arc::new(Mutex::new(None));
    let observed = Arc::new(AtomicUsize::new(0));

    let (slot, count) = (listener.clone(), observed.clone());
    worker.on_observer_added(move |_obs: Observer| {
        let (slot, count) = (slot.clone(), count.clone());
        async move {
            if count.fetch_add(1, Ordering::SeqCst) > 0 {
                return Ok(());
            }
            let url = std::env::var("PRIMARY_DATABASE_URL").unwrap_or_default();
            let mut conn = PgListener::connect(&url)
                .await
                .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            conn.listen("iii_row_changed")
                .await
                .map_err(|e| ObserveRejection::new("DB_ERROR", e.to_string()))?;
            *slot.lock().await = Some(conn);
            Ok(())
        }
    });

    let (slot, count) = (listener.clone(), observed.clone());
    worker.on_observer_removed(move |_obs: Observer| {
        let (slot, count) = (slot.clone(), count.clone());
        async move {
            if count.fetch_sub(1, Ordering::SeqCst) > 1 {
                return;
            }
            slot.lock().await.take();
        }
    });
    ```

For one function, pass its id to the same pair: The hook names in each SDK:

| Hook                    | Node / Browser                   | Python                             | Rust                                   | Go                                  |
| ----------------------- | -------------------------------- | ---------------------------------- | -------------------------------------- | ----------------------------------- |
| Added, every function   | `onObserverAdded(hook)`          | `on_observer_added(hook)`          | `on_observer_added(hook)`              | `OnObserverAdded(hook)`             |
| Added, one function     | `onObserverAdded(id, hook)`      | `on_observer_added(id, hook)`      | `on_observer_added_for(id, hook)`      | `OnObserverAddedFor(id, hook)`      |
| Removed, every function | `onObserverRemoved(hook)`        | `on_observer_removed(hook)`        | `on_observer_removed(hook)`            | `OnObserverRemoved(hook)`           |
| Removed, one function   | `onObserverRemoved(id, hook)`    | `on_observer_removed(id, hook)`    | `on_observer_removed_for(id, hook)`    | `OnObserverRemovedFor(id, hook)`    |
| Match, one function     | `onObservationMatch(id, hook)`   | `on_observation_match(id, hook)`   | `on_observation_match_for(id, rule)`   | `OnObservationMatchFor(id, rule)`   |
| Deliver, one function   | `onObservationDeliver(id, hook)` | `on_observation_deliver(id, hook)` | `on_observation_deliver_for(id, hook)` | `OnObservationDeliverFor(id, hook)` |

The `FunctionRef` has the same methods with the id filled in: `onObserverAdded(hook)` and its
siblings in Node, Python and Rust (`on_observer_added(hook)`), and `OnObserverAdded(hook)` in Go. In
Node, Rust and Go each method returns its receiver, so calls chain. In Python each returns the hook,
so it also works as a decorator, and `on_observer_added("id")` without a hook is a decorator
factory. Added, removed and deliver hooks may be sync or async in Node and Python. A match predicate
and key functions are sync, since they run on every call. In Rust a hook is an async closure or a
type that implements `AddedHook`, `RemovedHook` or `DeliverHook`.

A match hook is a predicate or a pair of key functions (see
[Match observers to calls](#match-observers-to-calls)):

| SDK            | Predicate                                  | Keys                                           |
| -------------- | ------------------------------------------ | ---------------------------------------------- |
| Node / Browser | `onObservationMatch(id, (obs, call) => …)` | `onObservationMatch(id, { observer, call })`   |
| Python         | `on_observation_match(id, predicate)`      | `on_observation_match(id, observer=…, call=…)` |
| Rust           | `Match::predicate(f)`                      | `Match::keys(observer_keys, call_keys)`        |
| Go             | `iii.MatchFunc(f)`                         | `iii.MatchKeys(observerKeys, callKeys)`        |

Pass `null` (`None` in Python, `nil` in Go) to remove a hook. Rust removes hooks with `clear_*`
methods: `clear_observer_added()`, `clear_observer_removed()`, `clear_observation_match()` and
`clear_observation_deliver()` on the `FunctionRef`; `clear_observer_added_for(id)`,
`clear_observer_removed_for(id)`, `clear_observation_match_for(id)` and
`clear_observation_deliver_for(id)` on the client; and `clear_observer_added()` and
`clear_observer_removed()` on the client for the worker-wide hooks.

Hooks are stored by function id. They stay in place across `unregister()` and a later registration
of the same id, and they can be set before the function is registered. Once the worker's connection
is registered, the SDK logs a warning for each hook id the worker has not registered, which catches
a mistyped id.

A hook for one function is set by id (see [Hooks](#hooks)) or chained on the `FunctionRef` that
`registerFunction` returns. Each method returns its receiver, so calls chain. Added, removed and
deliver hooks can be sync or async. A match predicate is sync, since it runs on every call. In Rust
a hook is an async closure or a type that implements `AddedHook`, `RemovedHook` or `DeliverHook`.
Implement these traits with native `async fn`, without `#[async_trait]`: their futures must be
`Send` and may borrow `self` across `.await`. See
[Implement Rust hooks with native async fn](../upgrading/from-0-25-x#implement-rust-hooks-with-native-async-fn).

Removing a hook returns the function to its default (see [Hooks](#hooks)).

Hooks are stored by function id. They stay in place across `unregister()` and a later registration
of the same id, and they can be set before the function is registered. Once the worker's connection
is registered, the SDK logs a warning for each hook id the worker has not registered, which catches
a mistyped id.

#### Reject an observer

An observer is accepted when every `onObserverAdded` that applies to it resolves. The SDK then
acknowledges it to the engine, and the observer becomes `active`. So its database trigger exists
before the first call it must receive.

An `onObserverAdded` that throws rejects the observer. A thrown `ObserveRejection(code, message)`
sets the code the consumer's `ready()` fails with; any other error is `OBSERVE_REJECTED`.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { ObserveRejection } from "iii-sdk";

    worker.onObserverAdded("database::on-row-changed", async (obs) => {
      const { db } = obs.args as { db: string };
      // accept: a hook that returns accepts the observer
      if (db === "primary") return;
      // reject: a thrown ObserveRejection sets the code ready() fails with
      throw new ObserveRejection("UNKNOWN_DB", `no database '${db}'`);
    });
    ```

  </Tab>

#### No replay of past executions

iii does not store observation history. A hook reacts only to the executions of its function that
happen after the hook is registered, and an observer receives only the calls that happen after it is
accepted.

#### Reject an observer later

An observer that the function accepted can become invalid later. For example, a configuration reload
can remove the resource that the observer watches. `obs.reject(code, message)` stops delivery to the
observer immediately, and the SDK runs `onObserverRemoved` next, connected or not. The engine moves
the observer to `error` with that code. If the connection is lost, the SDK sends the rejection again
after it reconnects.

    ```typescript
    const rowChanged = worker.registerFunction(
      "database::on-row-changed",
      (change: RowChange) => change,
      {
        private: true,
        // the args an observer of this function passes
        args_format: {
          type: "object",
          properties: { db: { type: "string" }, table: { type: "string" }, op: { type: "string" } },
          required: ["db", "table", "op"],
        },
      },
    );

    function rejectDroppedDatabases() {
      for (const obs of rowChanged.observers()) {
        if (!pools.has(obs.args.db as string)) {
          obs.reject("UNKNOWN_DB", `no database '${obs.args.db}'`);
        }
      }
    }
    ```

### Observation lifecycle

These hooks run per call. An observation is one call of the function reaching, or being considered
for, one observer.

<Note>
  An observer's args and the call settle the choice in
  [`onObservationMatch`](#match-observers-to-calls). Choose in `onObservationDeliver` when the
  choice compares observers with each other, or when making it produces part of the payload.
</Note>

#### `onObservationMatch(obs, call)`

By default, every call is observed by every observer. Setting this hook overrides that: it selects,
for one call, which observers get it, as a predicate that returns a boolean. iii then applies each
matched observer's `capture` and filters as usual.


#### `onObservationDeliver(call, observers)`

By default, iii carries out each observation: it runs the target of every matched observer whose
capture and filters match the call, and gives the caller the handler's return value. Setting this
hook overrides that: you deliver the call yourself and decide what is returned to the caller.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    type RowChange = {
      db: string;
      table: string;
      op: "insert" | "update" | "delete";
      row: Record<string, unknown>;
    };

    worker.onObservationDeliver("database::on-row-changed", async (call, observers) => {
      const change = call.input as RowChange;
      // the observer that names this table, before one that names every table
      const observer =
        observers.find((obs) => obs.args.table === change.table) ??
        observers.find((obs) => obs.args.table === "*");
      if (!observer || !observer.matches(call)) return { delivered: false };
      return worker.call({ observer, payload: change }); // the caller gets the target's result
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python

        observer = next((obs for obs in observers if obs.args["table"] == change["table"]), None)

            observer = next((obs for obs in observers if obs.args["table"] == "*"), None)
        if observer is None or not observer.matches(call):
            return {"delivered": False}
        return await worker.call_async({"observer": observer, "payload": change})  # the target's result
    ```

#### Match observers to calls

`onObservationMatch` selects, for each call, which observers get it, so a function can route its
calls by the args of its observers. The predicate receives the observer and the call, and returns a
boolean: `true` when that observer gets this call, `false` when it does not. The SDK calls it once
for each active observer, before that observer's capture and filters; a predicate that throws counts as
no match for that observer. iii does everything else as usual: each observer's capture, filters
and policy still apply.

<Tabs>

## Producing events with observers

Function observation is not limited to input/output. Functions can use the same observer pattern to
produce events during execution. Do it with a second function that this worker hosts, and call it
with the event as the payload. That second function works as the event source:

- Its handler returns its input, so one call is one event.
- Each call runs the observers of the event source.
- The producing function gets the handler's return value, so it keeps running.
- `private: true` keeps the calls to this worker: other workers can observe the event source, and
  only this worker can call it (see [Private functions](#private-functions)).

`FunctionRef.isObserved()` returns true when the event source has at least 1 active observer. It has
minimal overhead, so it can be used to skip events that are not being observed.

<Tabs>

    ```typescript
      await worker.call({ function_id: "database::on-row-changed", payload: { db, table, op, row } });

    // from any handler of this worker, for each changed row
    ```

### Send an observer its initial state

A source sends one observer something of its own, such as its current state when the observer is
added or an event it missed, by calling through that observer. The call runs that observer's target
and no other.

`obs.accepted()` resolves once the SDK has acknowledged the observer. A call made after it resolves
reaches an active observer, since the engine handles a connection's messages in order, as long as
the observer's target is registered: an observer whose target is not registered yet stays `pending`,
and the call fails with `OBSERVER_NOT_ACTIVE`. The observer becomes active after its
`onObserverAdded` returns, so the hook starts a task that waits for `accepted()` and then makes the
call. `accepted()` fails for an observer rejected first, such as one whose `onObserverAdded` throws,
and the task then sends nothing.

The target receives the payload as given, with the observer's registration metadata. Send what your
function's targets expect.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { CallAction } from "iii-sdk";
    import { Pool } from "pg";

    const pools = new Map([["primary", new Pool({ connectionString: process.env.PRIMARY_DATABASE_URL })]]);

    worker.onObserverAdded("database::on-row-changed", (obs) => {
      // send the table's row count once the observer is active
      void obs
        .accepted()
        .then(async () => {
          const { db, table } = obs.args as { db: string; table: string };
          const pool = pools.get(db);
          const counted = pool ? await pool.query(`SELECT count(*)::int AS n FROM ${table}`) : undefined;
          await worker.call({
            observer: obs,
            payload: { table, rows: counted ? counted.rows[0].n : 0 },
            action: CallAction.Void(),
          });
        })
        .catch(() => {
          // a rejected observer gets nothing
        });
    });
    ```

  </Tab>

    ```go
            table, _ := obs.Args["table"].(string)
            rows := 0
            if pool, ok := pools[db]; ok {
                _ = pool.QueryRowContext(context.Background(), "SELECT count(*) FROM "+table).Scan(&rows)
            }
            payload, _ := json.Marshal(map[string]any{"table": table, "rows": rows})
            worker.Call(context.Background(), iii.CallRequest{
                Observer: obs,
                Payload:  payload,
                Action:   iii.VoidAction(),
            })
        }()
        return nil
    })
    ```

## Call a target through its observer

iii delivers a call to every matched observer and does not wait for the targets. When the worker
that hosts a function must reach one observer on its own, it makes a call that names that observer.
The call runs that observer's target and resolves to the target's result.

In one line, the call is:

    ```rust
            let payload = json!(HttpRequest { path_params: route.params.clone(), ..request });
            self.worker.call(CallRequest::observer(&route.obs, payload)).await
    ```

The http worker does this for every request. `http::on-request` returns its input, one observer with
`{ method, path }` args declares one route, and the deliver hook picks the route of the request and
calls through that route's observer. The target's return value is the response. The full flow:

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { ObserveRejection, registerWorker } from "iii-sdk";

    const worker = registerWorker("ws://127.0.0.1:49134", { workerName: "http" });

    type RouteArgs = { method: string; path: string };
    const routes = new Map<string, string>(); // "GET /orders/:id" -> observer id
    const routeKey = (args: RouteArgs) => `${args.method} ${args.path}`;

    // one call is one request: the handler returns its input
    worker.registerFunction("http::on-request", (request: unknown) => request, {
      args_format: {
        type: "object",
        properties: { method: { type: "string" }, path: { type: "string" } },
        required: ["method", "path"],
      },
      private: true,
    });

    worker.onObserverAdded("http::on-request", (obs) => {
      const key = routeKey(obs.args as RouteArgs);
      if (routes.has(key)) throw new ObserveRejection("HTTP_ROUTE_CONFLICT", `${key} is taken`);
      routes.set(key, obs.id);
    });

    worker.onObserverRemoved("http::on-request", (obs) => {
      for (const [key, id] of routes) if (id === obs.id) routes.delete(key);
    });

    worker.onObservationDeliver("http::on-request", async (call, observers) => {
      const request = call.input as RouteArgs;
      const obs = observers.find((o) => o.id === routes.get(routeKey(request)));
      if (!obs) return { status_code: 404, body: "NOT_FOUND" };
      if (!obs.matches(call)) return { status_code: 422, body: "FILTERS_NOT_MET" };
      return worker.call({ observer: obs, payload: call.input }); // the target's result
    });

    // the server: one call per request, and its result is the HTTP response
    const response = await worker.call({
      function_id: "http::on-request",
      payload: { method: "GET", path: "/orders/:id" },
    });
    ```

## Registration options

`registerFunction` takes the options that describe a function to the engine; the
[SDK references](../reference/sdk-node) list them. Three of them change what observation means:

### Private functions

An event source is observed by everyone and called only by its own worker. A call from another
worker would be a forged request or row change carrying the source's identity. `private: true`
expresses that:

- The engine accepts a call of a private function only from the connection that hosts it. Any other
  connection, and the engine itself, gets `FORBIDDEN`. A call through an observer is the observing
  worker's call, and an activation is the engine's.
- A private function is observable, and its observers receive every call its worker makes.
- A private function cannot be an observer's target (`FORBIDDEN` at `observe`).
- A worker's call to its own private function passes the input and the result by reference. No other
  worker can read either value, so the SDK copies neither, and the handler and hooks treat both as
  read-only. With `NODE_ENV=development`, the Node SDK freezes them, so a write throws. An
  observer's target receives its own copy, serialized when the call matches.

Any function can be private; event sources are the common case.

### Prevent function observation

Some functions must stay unobserved, for example because their input carries credentials. Register
them with `observable: false`. Every `observe` of them fails with `NOT_OBSERVABLE`.

### One host per function

A function id has one host per namespace, the worker that registers it and runs its handler (see
[Namespaces](../using-iii/namespaces)). Observer hooks therefore run once per observer, in that
host.

When the host disconnects, the observers of its functions go `pending`. The next worker that
registers the function receives those observers and runs its hooks for each one: the added hook, or
the worker-level pair, so the setup runs again in the new host. An observer becomes active again
once its hook returns. Run one instance of a worker that hosts an event source, and let the platform
restart it: stop the old instance before the new one starts (`strategy: Recreate` in Kubernetes).

## The `Observer` object

Hooks get an `Observer`: the record of what the consumer asked for. Who observes, the observer's
metadata and its policy stay with the engine. The object stays the same for the full life of the
observer, so the worker can keep it, for example in a map.

| Member                  | Meaning                                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | The observer id.                                                                                                                    |
| `function_id`           | The observed function.                                                                                                              |
| `args`                  | The observer's args, already validated against `args_format` by the engine.                                                         |
| `filters`               | The observer's filters in [normal form](../reference/filters#normal-form).                                                          |
| `target`                | The target function id.                                                                                                             |
| `capture`               | Which parts of the call its payload carries, and with them which calls the observer gets (see [`capture`](../using-iii/observers#capture)). |
| `matches(call)`         | Evaluates the observer's capture and filters on a call.                                                                             |
| `accepted()`            | Resolves once the SDK has acknowledged the observer. See [Send an observer its initial state](#send-an-observer-its-initial-state). |
| `reject(code, message)` | Late rejection of an active observer. See [Reject an observer later](#reject-an-observer-later).                                    |

To reject an observer from `onObserverAdded`, throw `new ObserveRejection(code, message)`.

## The `Call` object

`onObservationMatch` and `onObservationDeliver` receive the call:

| Field           | Meaning                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------- |
| `function_id`   | The function that was called.                                                               |
| `invocation_id` | The id of the call.                                                                         |
| `status`        | `success` or `error`.                                                                       |
| `input`         | The call's input.                                                                           |
| `output`        | The handler's return value: what observers observe.                                         |
| `error`         | `{ code, message }`, what the handler threw.                                                |
| `caller`        | Who made the call. See [Caller and causality](../using-iii/observers#caller-and-causality). |
| `metadata`      | The call's metadata.                                                                        |
