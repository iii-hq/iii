Every function you register is already observable. Each time it runs, iii runs the target of every
[observer](../using-iii/observers) watching it, and you add no code for that. To publish an event,
register a function for it and call that function whenever the event happens:

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    type FileChanged = { path: string; event: "created" | "modified" | "deleted" };

    worker.registerFunction("files::on-change", async (change: FileChanged) => change);

    // whenever a file changes:
    await worker.trigger({ function_id: "files::on-change", payload: change });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    worker.register_function("files::on-change", lambda change: change)

    # whenever a file changes:
    worker.trigger({"function_id": "files::on-change", "payload": {"path": path, "event": "modified"}})
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::protocol::TriggerRequest;
    use iii_sdk::{Error, RegisterFunction};
    use schemars::JsonSchema;
    use serde::{Deserialize, Serialize};
    use serde_json::json;

    #[derive(Serialize, Deserialize, JsonSchema)]
    struct FileChanged {
        path: String,
        event: String,
    }

    worker.register_function(
        "files::on-change",
        RegisterFunction::new(|change: FileChanged| Ok::<_, Error>(change)),
    );

    // whenever a file changes:
    let change = json!({ "path": path, "event": "modified" });
    worker.trigger(TriggerRequest::new("files::on-change", change)).await?;
    ```

  </Tab>
  <Tab title="Go">
    ```go
    client.RegisterFunction("files::on-change", func(ctx context.Context, data json.RawMessage) (any, error) {
        return data, nil
    })

    // whenever a file changes:
    change, _ := json.Marshal(map[string]string{"path": path, "event": "modified"})
    client.Trigger(ctx, iii.TriggerRequest{FunctionID: "files::on-change", Data: change})
    ```

  </Tab>
</Tabs>

No hooks, no `observe` option, no list of observers: whoever observes `files::on-change` gets every
call that passes their filters.

This default is **auto delivery**, and most sources need nothing more. The rest of this page is for
the worker that hosts a function (its owner) when it wants to **override the default**:

- run code when an observer is added or removed, for example to start expensive work only while
  someone is watching ([Know when you are observed](#know-when-you-are-observed));
- take control of which observer gets which event, from what each observer asked for in its `args`
  ([Owner delivery](#owner-delivery));
- accept the old `registerTrigger` calls of a trigger type the function replaces
  ([Accept old triggers](#accept-old-triggers)).

<Warning>
  With owner delivery, calling your function no longer reaches any observer. From then on your code
  decides when each observer's target runs, and nothing is delivered until you call `obs.emit` or
  `obs.call`. If every observer should see every call, stay on auto delivery.
</Warning>

In 0.25 this replaces `registerTriggerType`: a trigger type becomes a function with an `observe`
descriptor, and a trigger becomes an observer. To move an existing trigger type, see
[Upgrading from 0.24.x](../upgrading/from-0-24-x#move-a-trigger-type-to-an-observable-function).

## Do you need owner delivery?

| You want                                                                                     | Use                                                                                      |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Observers to react to every call of your function (filters narrow it)                        | Auto delivery. Write nothing; call your function.                                        |
| To start or stop work while anyone observes, but still deliver every call                    | Auto delivery with hooks. See [Know when you are observed](#know-when-you-are-observed). |
| Each observer to set something up and get only its own events (an interval, a path, a table) | Owner delivery.                                                                          |
| An answer back from the observer's target (an HTTP response, a queue ack)                    | Owner delivery with `obs.call`.                                                          |

## The `observe` descriptor

Pass `observe` when you register the function:

| Field                 | Default | Meaning                                                                                                              |
| --------------------- | ------- | -------------------------------------------------------------------------------------------------------------------- |
| `delivery`            | `auto`  | `auto`: every invocation is an event, offered to every observer. `owner`: your code hands events to observers.       |
| `args_format`         | none    | Owner delivery only: the JSON Schema of the observers' `args`. The engine rejects other args with `INVALID_ARGS`.    |
| `legacy_trigger_type` | none    | Accept old `registerTrigger({ type })` calls for this trigger type. See [Accept old triggers](#accept-old-triggers). |
| `allow`               | `true`  | `false` refuses every observer with `NOT_OBSERVABLE`.                                                                |
| `onObserverAdded`     | none    | Runs once per added observer, before the engine marks it `active`. Throw to reject it.                               |
| `onObserverRemoved`   | none    | Runs once per removed observer. It cannot fail; errors are logged.                                                   |

Only the first four fields travel to the engine; the hooks stay in your process. The names follow
each SDK's conventions:

| SDK     | Where                                                                               | Hooks                                                               |
| ------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Node    | `registerFunction(id, handler, { observe: { ... } })`                               | `onObserverAdded(obs)`, `onObserverRemoved(obs)`                    |
| Browser | same as Node                                                                        | same as Node                                                        |
| Python  | `register_function(id, handler, observe=ObserveHooks(...))` or a subclass           | `on_observer_added(obs)`, `on_observer_removed(obs)`, sync or async |
| Rust    | `RegisterFunction::new(..).observe(Observe::owner().args_format::<T>().handler(h))` | `ObserveHandler::on_observer_added` / `on_observer_removed`         |
| Go      | `RegisterFunctionOptions{Observe: &iii.ObserveHooks{...}}`                          | `OnObserverAdded(ctx, obs)`, `OnObserverRemoved(ctx, obs)`          |

`args_format` with `delivery: 'auto'` fails at registration with `INVALID_OBSERVE_DESCRIPTOR`: an
auto function's events are its invocations, offered to every observer, so there is nothing to route
by.

### Hook rules

- `onObserverAdded` runs before the SDK acknowledges the observer to the engine. Whatever it adds to
  your own index is in place before the observer turns `active`, so the first event after `ready()`
  resolves reaches it.
- Throwing rejects the observer: an `ObserveRejection(code, message)` sets the code the observer's
  `ready()` fails with; any other error is `OBSERVE_REJECTED`.
- The hooks of one function run one at a time, in the engine's order. Hooks of different functions
  may run concurrently.
- A hook still running after 30 seconds counts as failed (`OWNER_TIMEOUT`, the engine enforces the
  same `observers.owner_ack_timeout_ms`), and the next hook may start.
- `onObserverRemoved` runs on `dispose()`, policy exhaustion (`max_fires`, expiry), when the
  observing worker does not come back within its grace period, and when a reconnect no longer lists
  the observer.

### The `Observer` object

Hooks receive an `Observer`: the observer as its owner sees it. It never exposes the observer's
metadata, policy, or observing worker. The object stays the same for the observer's whole lifetime,
so keep it in your own index.

| Member                  | Meaning                                                                                                                                   |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                    | The observer id.                                                                                                                          |
| `function_id`           | Your function.                                                                                                                            |
| `args`                  | The observer's args, already validated against `args_format` by the engine.                                                               |
| `filters`               | The observer's filters in [normal form](../reference/filters#normal-form). The SDK applies them for you.                                  |
| `target`                | The target function id.                                                                                                                   |
| `capture`, `on`         | What the observer captures, and `on` (auto delivery only).                                                                                |
| `legacy`                | `{ trigger_type, config }` when the engine made the observer from an old `registerTrigger`.                                               |
| `matches(doc)`          | Evaluates the observer's filters on `{ input?, output?, error?, caller?, metadata? }`.                                                    |
| `emit(event)`           | Owner delivery, fire-and-forget. Returns `false` and sends nothing when the filters reject the event or the observer is no longer active. |
| `call(payload)`         | Owner delivery, request/response: invokes the target and returns its result.                                                              |
| `reject(code, message)` | Late rejection of an active observer. See [Reject an observer later](#reject-an-observer-later).                                          |

Language specifics: Python has `call` (blocking) and `call_async`; Rust has `id()`, `args::<T>()`,
`args_value()`, `legacy()`, `emit(&event) -> Result<bool, Error>` and `call::<R>(payload).await`; Go
has `Args` (a map), `DecodeArgs(&v)`, `Legacy`, `Emit(ctx, event) (bool, error)` and
`Call(ctx, payload) (json.RawMessage, error)`.

## Know when you are observed

The next step up keeps auto delivery (every call still reaches every observer) and adds hooks, for
example to log who subscribes or to start expensive work only while someone observes.
`FunctionRef.isObserved()` (`is_observed()` in Python and Rust, `client.IsObserved(id)` in Go)
answers in one load, so a hot path can skip building events nobody receives.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    const prices = worker.registerFunction("prices::on-change", async (change: PriceChange) => change, {
      observe: {
        onObserverAdded(obs) {
          console.log(`${obs.target} now observes prices::on-change`);
        },
      },
    });

    // in the price feed loop
    if (prices.isObserved()) {
      await worker.trigger({ function_id: "prices::on-change", payload: change });
    }
    ```

  </Tab>
  <Tab title="Python">

Because the worker calls its own function, the call runs in-process
([local dispatch](../using-iii/observers#local-dispatch)) and reaches the engine only when an
observer's filters match.

## Owner delivery

With `delivery: 'owner'` you take over from the engine. Invocations of your function are no longer
offered to every observer; your code decides which observers each event is for, from their `args`,
and hands it over.

|                      | Auto (the default)                                         | Owner                                                                       |
| -------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| An event is          | every invocation of the function                           | what your code hands to an observer with `obs.emit` or `obs.call`           |
| Observer `args`      | not accepted (`INVALID_ARGS`)                              | validated against your `args_format`, then read by your hooks               |
| Filters evaluated by | the engine (routed calls) or the hosting SDK (local calls) | your SDK, each time you hand an event to the observer                       |
| When the target runs | after the observed invocation completes, per `on`          | when your code decides, usually inside the function's own handler           |
| The target's result  | discarded                                                  | discarded for `obs.emit`; returned to you for `obs.call`                    |
| Examples             | any regular function, the engine-hosted event sources      | sources that need setup per observer: a schedule, a route, a table to watch |

Owner delivery always takes three pieces, and leaving one out means observers stay `active` but
never fire:

1. **`onObserverAdded` keeps the `Observer`** in your own index, keyed by its `args`, and starts
   whatever produces events (a timer, a watcher). It must not wait for events itself: it has 30
   seconds before the observer fails with `OWNER_TIMEOUT`, and an `emit` from inside it returns
   `false` because the observer is not `active` yet.
2. **Your producer calls your function** when something happens, as with auto delivery.
3. **Your function's handler emits**: it looks up the observers the event belongs to and calls
   `obs.emit(event)` (or `obs.call(payload)`) on each. This is the step that runs their targets.

`onObserverRemoved` takes the observer out of the index and stops what step 1 started once nobody
needs it.

The two ways to hand over an event:

|                 | `obs.emit(event)`                                                                                                                    | `obs.call(payload)`                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Use for         | events whose result you do not need: a tick, a row change                                                                            | requests that need an answer: an HTTP response, a queue acknowledgement |
| The target gets | the [`Observed` envelope](../using-iii/observers#what-the-target-receives) with `input` (or the event alone with `deliver: 'input'`) | your `payload`                                                          |
| Returns         | `true` when the event was handed over, `false` when the filters rejected it                                                          | the target's result                                                     |
| Wire cost       | one batched report item, then one activation from the engine                                                                         | one invocation through the engine                                       |

Only your worker may invoke an owner-delivered function: the engine refuses a call to it from any
other worker (or from the engine itself) with `FORBIDDEN`, so nobody can pass off an event as yours.

The SDK applies the observer's filters in both: `emit` returns `false`, and `call` fails with
`FILTERS_NOT_MATCHED`, without sending anything. Use `obs.matches({ input })` when you want to know
first. Both go through the engine, which applies the observer's policy (`max_fires`, expiry,
`max_in_flight`), adds its metadata, and enforces the loop guard. Both throw `NOT_OWNER_DELIVERED`
on an auto function.

`emit` never waits. When you emit faster than the targets take, the observers' queues fill and the
engine stops reading your worker's connection until they have room again, for at most 250 ms.
Meanwhile the SDK keeps what it can in its bounded report buffer and drops the rest, counted as
`BUFFER_FULL`, and everything else your worker sends (its calls, its answers to calls) waits behind
its reports. After each hold the engine reads your worker's connection for at least a quarter as
long before it holds it again, and drops what overflows meanwhile as `OVERFLOW`: your worker is held
at most four fifths of the time.

An emitted event travels in the SDK's report, like a
[local call](../using-iii/observers#local-dispatch): values JSON cannot hold arrive as `null` (or
U+FFFD for a lone surrogate), an event larger than the 8 MiB report buffer is dropped as
`TOO_LARGE`, and a report lost with a dropped connection is not sent again.

The event's `caller` follows where you call `emit`: inside your function's own handler, the event is
that invocation (its id and its caller); inside another handler, that handler is the caller; outside
any handler, only your worker. That is why the examples below trigger their own function and emit
from its handler.

### Example: a file watcher that emits

`files::watch` is the smallest complete owner-delivered source. Each observer names the file it
cares about in its args (`{ path }`), and gets the changes to that file only. The numbered comments
mark the three pieces above. The worker polls each file once a second, with one poller per watched
path however many observers share it.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { type Stats, unwatchFile, watchFile } from "node:fs";
    import type { Observer } from "iii-sdk";

    type FileChanged = { path: string; size_bytes: number };

    const watched = new Map<string, Map<string, Observer>>(); // path → its observers

    worker.registerFunction(
      "files::watch",
      async (change: FileChanged) => {
        // 3. Hand the change to the observers of that path.
        for (const obs of watched.get(change.path)?.values() ?? []) {
          obs.emit(change);
        }
        return null;
      },
      {
        description: "Fires when a watched file changes. Observe it with args { path }.",
        observe: {
          delivery: "owner",
          args_format: {
            type: "object",
            additionalProperties: false,
            required: ["path"],
            properties: { path: { type: "string" } },
          },
          onObserverAdded(obs) {
            // 1. Keep the observer, and start polling its path if nobody else watches it.
            const path = obs.args.path as string;
            let observers = watched.get(path);
            if (!observers) {
              observers = new Map();
              watched.set(path, observers);
              watchFile(path, { interval: 1000 }, (curr: Stats) => {
                // 2. The poller calls the function.
                worker
                  .trigger({ function_id: "files::watch", payload: { path, size_bytes: curr.size } })
                  .catch((err) => console.error("file change failed", err));
              });
            }
            observers.set(obs.id, obs);
          },
          onObserverRemoved(obs) {
            const path = obs.args.path as string;
            const observers = watched.get(path);
            observers?.delete(obs.id);
            if (observers?.size === 0) {
              unwatchFile(path); // last observer of this path: stop polling it
              watched.delete(path);
            }
          },
        },
      },
    );
    ```

  <Tab title="Python">
    ```python
    import os
    import threading

    from iii import ObserveHooks

    watched: dict[str, dict] = {}  # path → {"observers": {id: Observer}, "stop": Event}
    lock = threading.Lock()

    def poll(path: str, stop: threading.Event) -> None:
        last = None
        while not stop.wait(1.0):
            try:
                st = os.stat(path)
            except FileNotFoundError:
                continue
            if last is not None and st.st_mtime_ns != last:
                # 2. The poller calls the function.
                worker.trigger({
                    "function_id": "files::watch",
                    "payload": {"path": path, "size_bytes": st.st_size},
                })
            last = st.st_mtime_ns

    class WatchHooks(ObserveHooks):
        delivery = "owner"
        args_format = {
            "type": "object",
            "additionalProperties": False,
            "required": ["path"],
            "properties": {"path": {"type": "string"}},
        }

        def on_observer_added(self, obs):
            # 1. Keep the observer, and start polling its path if nobody else watches it.
            path = obs.args["path"]
            with lock:
                entry = watched.get(path)
                if entry is None:
                    stop = threading.Event()
                    threading.Thread(target=poll, args=(path, stop), daemon=True).start()
                    entry = watched[path] = {"observers": {}, "stop": stop}
                entry["observers"][obs.id] = obs

        def on_observer_removed(self, obs):
            path = obs.args["path"]
            with lock:
                entry = watched.get(path)
                if entry is None:
                    return
                entry["observers"].pop(obs.id, None)
                if not entry["observers"]:
                    entry["stop"].set()  # last observer of this path: stop polling it
                    del watched[path]

    def on_change(change: dict) -> None:
        # 3. Hand the change to the observers of that path.
        with lock:
            entry = watched.get(change["path"])
            observers = list(entry["observers"].values()) if entry else []
        for obs in observers:
            obs.emit(change)

    worker.register_function(
        "files::watch",
        on_change,
        description="Fires when a watched file changes. Observe it with args { path }.",
        observe=WatchHooks(),
    )
    ```

    ```rust
    use std::collections::HashMap;
    use std::sync::{Arc, Mutex};
    use std::time::Duration;

    use iii_sdk::protocol::TriggerRequest;
    use iii_sdk::{
        Error, IIIClient, Observe, ObserveHandler, ObserveRejection, Observer, RegisterFunction,
    };
    use schemars::JsonSchema;
    use serde::{Deserialize, Serialize};
    use serde_json::json;

    #[derive(Deserialize, JsonSchema)]
    #[serde(deny_unknown_fields)]
    struct WatchArgs {
        path: String,
    }

    #[derive(Serialize, Deserialize, JsonSchema)]
    struct FileChanged {
        path: String,
        size_bytes: u64,
    }

    /// path → the observers of that path and the task that polls it
    #[derive(Clone)]
    struct Watched {
        iii: IIIClient,
        by_path: Arc<Mutex<HashMap<String, (Vec<Observer>, tokio::task::JoinHandle<()>)>>>,
    }

    async fn poll(iii: IIIClient, path: String) {
        let mut last = None;
        let mut interval = tokio::time::interval(Duration::from_secs(1));
        loop {
            interval.tick().await;
            let Ok(meta) = tokio::fs::metadata(&path).await else { continue };
            let modified = meta.modified().ok();
            if last.is_some() && modified != last {
                // 2. The poller calls the function.
                let change = json!({ "path": path, "size_bytes": meta.len() });
                let _ = iii.trigger(TriggerRequest::new("files::watch", change)).await;
            }
            last = modified;
        }
    }

    #[async_trait::async_trait]
    impl ObserveHandler for Watched {
        async fn on_observer_added(&self, obs: &Observer) -> Result<(), ObserveRejection> {
            // 1. Keep the observer, and start polling its path if nobody else watches it.
            let WatchArgs { path } = obs.args()?; // validated by the engine
            let mut by_path = self.by_path.lock().unwrap();
            let (observers, _) = by_path.entry(path.clone()).or_insert_with(|| {
                let task = tokio::spawn(poll(self.iii.clone(), path));
                (Vec::new(), task)
            });
            observers.push(obs.clone());
            Ok(())
        }

        async fn on_observer_removed(&self, obs: &Observer) {
            self.by_path.lock().unwrap().retain(|_, (observers, task)| {
                observers.retain(|o| o.id() != obs.id());
                if observers.is_empty() {
                    task.abort(); // last observer of this path: stop polling it
                }
                !observers.is_empty()
            });
        }
    }

    let watched = Watched { iii: worker.clone(), by_path: Default::default() };

    worker.register_function(
        "files::watch",
        RegisterFunction::new({
            let watched = watched.clone();
            move |change: FileChanged| {
                // 3. Hand the change to the observers of that path.
                let observers = watched
                    .by_path
                    .lock()
                    .unwrap()
                    .get(&change.path)
                    .map(|(observers, _)| observers.clone())
                    .unwrap_or_default();
                for obs in observers {
                    obs.emit(&change)?;
                }
                Ok::<_, Error>(())
            }
        })
        .description("Fires when a watched file changes. Observe it with args { path }.")
        .observe(Observe::owner().args_format::<WatchArgs>().handler(watched.clone())),
    );
    ```

    ```go
    type fileChanged struct {
        Path      string `json:"path"`
        SizeBytes int64  `json:"size_bytes"`
    }

    type watch struct {
        observers map[string]*iii.Observer
        stop      chan struct{}
    }

    var (
        watchMu sync.Mutex
        watched = map[string]*watch{} // path → its observers and their poller
    )

    func poll(client *iii.Client, path string, stop chan struct{}) {
        ticker := time.NewTicker(time.Second)
        defer ticker.Stop()
        var last time.Time
        for {
            select {
            case <-stop:
                return
            case <-ticker.C:
                info, err := os.Stat(path)
                if err != nil {
                    continue
                }
                if !last.IsZero() && !info.ModTime().Equal(last) {
                    // 2. The poller calls the function.
                    data, _ := json.Marshal(fileChanged{Path: path, SizeBytes: info.Size()})
                    client.Trigger(context.Background(), iii.TriggerRequest{FunctionID: "files::watch", Data: data})
                }
                last = info.ModTime()
            }
        }
    }

    func watchedPath(obs *iii.Observer) string {
        var args struct {
            Path string `json:"path"`
        }
        _ = obs.DecodeArgs(&args) // validated by the engine
        return args.Path
    }

    func registerWatch(client *iii.Client) error {
        return client.RegisterFunction("files::watch", func(ctx context.Context, data json.RawMessage) (any, error) {
            var change fileChanged
            if err := json.Unmarshal(data, &change); err != nil {
                return nil, err
            }
            // 3. Hand the change to the observers of that path.
            watchMu.Lock()
            var observers []*iii.Observer
            if w := watched[change.Path]; w != nil {
                for _, obs := range w.observers {
                    observers = append(observers, obs)
                }
            }
            watchMu.Unlock()
            for _, obs := range observers {
                obs.Emit(ctx, change)
            }
            return nil, nil
        }, iii.RegisterFunctionOptions{Observe: &iii.ObserveHooks{
            Delivery:   iii.DeliveryOwner,
            ArgsFormat: json.RawMessage(`{"type":"object","additionalProperties":false,"required":["path"],"properties":{"path":{"type":"string"}}}`),
            OnObserverAdded: func(ctx context.Context, obs *iii.Observer) error {
                // 1. Keep the observer, and start polling its path if nobody else watches it.
                path := watchedPath(obs)
                watchMu.Lock()
                defer watchMu.Unlock()
                w := watched[path]
                if w == nil {
                    w = &watch{observers: map[string]*iii.Observer{}, stop: make(chan struct{})}
                    watched[path] = w
                    go poll(client, path, w.stop)
                }
                w.observers[obs.ID] = obs
                return nil
            },
            OnObserverRemoved: func(ctx context.Context, obs *iii.Observer) {
                path := watchedPath(obs)
                watchMu.Lock()
                defer watchMu.Unlock()
                if w := watched[path]; w != nil {
                    delete(w.observers, obs.ID)
                    if len(w.observers) == 0 {
                        close(w.stop) // last observer of this path: stop polling it
                        delete(watched, path)
                    }
                }
            },
        }})
    }
    ```

### Example: a timer that emits

The same shape as the file watcher, with one timer per interval instead of one poller per path.
`timer::on-tick` fires every `every_ms` milliseconds for the observers that asked for that interval.
It also declares a `request_format` and a stricter `args_format` (`every_ms` at least 100), so the
engine refuses an interval that would flood the targets before `onObserverAdded` runs.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import type { Observer } from "iii-sdk";

    type Tick = { every_ms: number; fired_at_ms: number };
    type Timer = { observers: Map<string, Observer>; handle: ReturnType<typeof setInterval> };

    const timers = new Map<number, Timer>(); // every_ms → observers and their timer

    worker.registerFunction(
      "timer::on-tick",
      async (tick: Tick) => {
        // One call per tick: hand it to the observers of that interval.
        for (const obs of timers.get(tick.every_ms)?.observers.values() ?? []) {
          obs.emit(tick); // false when the observer's filters reject the tick
        }
        return null;
      },
      {
        description: "Fires every `every_ms` milliseconds. Observe it with args { every_ms }.",
        request_format: {
          type: "object",
          additionalProperties: false,
          required: ["every_ms", "fired_at_ms"],
          properties: { every_ms: { type: "integer" }, fired_at_ms: { type: "integer" } },
        },
        observe: {
          delivery: "owner",
          args_format: {
            type: "object",
            additionalProperties: false,
            required: ["every_ms"],
            properties: { every_ms: { type: "integer", minimum: 100 } },
          },
          onObserverAdded(obs) {
            const every_ms = obs.args.every_ms as number;
            let timer = timers.get(every_ms);
            if (!timer) {
              // First observer of this interval: start one timer for all of them.
              const handle = setInterval(() => {
                worker
                  .trigger({ function_id: "timer::on-tick", payload: { every_ms, fired_at_ms: Date.now() } })
                  .catch((err) => console.error("tick failed", err));
              }, every_ms);
              timer = { observers: new Map(), handle };
              timers.set(every_ms, timer);
            }
            timer.observers.set(obs.id, obs);
          },
          onObserverRemoved(obs) {
            const every_ms = obs.args.every_ms as number;
            const timer = timers.get(every_ms);
            if (!timer) return;
            timer.observers.delete(obs.id);
            if (timer.observers.size === 0) {
              // Last observer of this interval: stop its timer.
              clearInterval(timer.handle);
              timers.delete(every_ms);
            }
          },
        },
      },
    );
    ```

    ```python
    import threading
    import time

    from iii import ObserveHooks

    timers: dict[int, dict] = {}  # every_ms → {"observers": {id: Observer}, "stop": Event}
    lock = threading.Lock()

    def run_timer(every_ms: int, stop: threading.Event) -> None:
        while not stop.wait(every_ms / 1000):
            worker.trigger({
                "function_id": "timer::on-tick",
                "payload": {"every_ms": every_ms, "fired_at_ms": int(time.time() * 1000)},

    class TimerHooks(ObserveHooks):
        delivery = "owner"
        args_format = {
            "type": "object",
            "additionalProperties": False,
            "required": ["every_ms"],
            "properties": {"every_ms": {"type": "integer", "minimum": 100}},
        }

        def on_observer_added(self, obs):
            every_ms = obs.args["every_ms"]
            with lock:
                timer = timers.get(every_ms)
                if timer is None:
                    # First observer of this interval: start one timer for all of them.
                    stop = threading.Event()
                    threading.Thread(target=run_timer, args=(every_ms, stop), daemon=True).start()
                    timer = timers[every_ms] = {"observers": {}, "stop": stop}
                timer["observers"][obs.id] = obs

            every_ms = obs.args["every_ms"]
            with lock:
                timer = timers.get(every_ms)
                if timer is None:
                    return
                timer["observers"].pop(obs.id, None)
                if not timer["observers"]:
                    # Last observer of this interval: stop its timer.
                    timer["stop"].set()
                    del timers[every_ms]

    def on_tick(tick: dict) -> None:
        with lock:
            timer = timers.get(tick["every_ms"])
            observers = list(timer["observers"].values()) if timer else []
        for obs in observers:
            obs.emit(tick)  # False when the observer's filters reject the tick
    ```

### Example: a command router that calls

The examples so far fire and forget. This one needs an answer back, so it uses `obs.call` instead of
`obs.emit`, and it rejects observers whose args clash. `chat::on-command` answers chat commands.
Each observer registers one command with args `{ command }`; the router calls that observer's target
and returns its result as its own.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { ObserveRejection, type Observer } from "iii-sdk";

    type CommandRequest = { command: string; text: string; user: string };
    type CommandReply = { reply: string };

    const commands = new Map<string, Observer>(); // command → observer

    worker.registerFunction(
      "chat::on-command",
      async (req: CommandRequest): Promise<CommandReply> => {
        const obs = commands.get(req.command);
        if (!obs) return { reply: `unknown command /${req.command}` };
        return obs.call<CommandReply>(req); // the target's result is this function's result
      },
      {
        description: "One invocation per chat command. Observe it with args { command }.",
        observe: {
          delivery: "owner",
          args_format: {
            type: "object",
            additionalProperties: false,
            required: ["command"],
            properties: { command: { type: "string" } },
          },
          onObserverAdded(obs) {
            const command = obs.args.command as string;
            if (commands.has(command)) {
              throw new ObserveRejection("COMMAND_TAKEN", `/${command} already has a handler`);
            }
            commands.set(command, obs);
          },
          onObserverRemoved(obs) {
            const command = obs.args.command as string;
            if (commands.get(command)?.id === obs.id) commands.delete(command);
          },
        },
      },
    );
    ```

### Errors of `obs.call`

`obs.call` fails with the target's own error, or with one of these codes:

| Code                                                          | When                                                                                                                             |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `FILTERS_NOT_MATCHED`                                         | The observer's filters reject the payload. Nothing was sent.                                                                     |
| `NOT_OWNER_DELIVERED`                                         | The function is auto-delivered.                                                                                                  |
| `OBSERVER_NOT_ACTIVE`                                         | The observer was removed or rejected meanwhile.                                                                                  |
| `OBSERVER_NOT_FOUND`, `NOT_FUNCTION_OWNER`, `TARGET_MISMATCH` | The engine does not know the observer, or this worker does not host the observed function.                                       |
| `LOOP_GUARD`                                                  | The call is deeper than `observers.max_observe_depth`.                                                                           |
| `OVERFLOW`                                                    | The observer has `max_in_flight` calls running. An owner call fails instead of queueing, because you are waiting for its result. |
| `TIMEOUT`                                                     | The target did not answer within `observers.activation_timeout_ms` (30 s by default).                                            |
| `function_not_found`                                          | The target is not registered.                                                                                                    |
| `payload_too_large`                                           | The activation is larger than the target worker accepts in one message. See [Event size](../using-iii/observers#event-size).     |

## Reject an observer later

An observer you accepted can become invalid, for example after a configuration reload removed the
resource it watches. `obs.reject(code, message)` takes it out of delivery at once; the engine moves
it to `error` with your code and then calls `onObserverRemoved`. The rejection survives a reconnect.

```typescript
for (const obs of feeds.observers()) {
  if (!config.sources.includes(obs.args.source as string)) {
    obs.reject("UNKNOWN_SOURCE", `source ${obs.args.source} was removed`);
  }
}
```

`FunctionRef.observers()` (`observers()` in Python and Rust, `client.Observers(id)` in Go) lists the
active observers as your hooks saw them.

## Refuse observers

Some functions should not be observed at all, for example because their input holds secrets.
Register them with `observe: { allow: false }` (`ObserveHooks(allow=False)` in Python,
`Observe::auto().allow(false)` in Rust, `Allow: &no` in Go). Every `observe` on them fails with
`NOT_OBSERVABLE`. RBAC still applies on top: an observer needs permission to invoke both the
observed function and the target.

## Accept old triggers

A function that replaces a trigger type can keep serving workers that still call
`registerTrigger({ type, function_id, config })`. Declare the type in `legacy_trigger_type`. The
excerpt below changes the [timer example](#example-a-timer-that-emits): its handler and index stay
as they were.

```typescript
import { ObserveRejection, type Observer } from "iii-sdk";

type Tick = { every_ms: number; fired_at_ms: number };
type TimerArgs = { every_ms: number };

// Observers made from an old registerTrigger have no args: their config is in obs.legacy.
const argsOf = (obs: Observer): TimerArgs =>
  (obs.legacy ? obs.legacy.config : obs.args) as TimerArgs;

worker.registerFunction(
  "timer::on-tick",
  async (tick: Tick) => {
    // ... hand the tick to the observers of tick.every_ms, as before
    return null;
  },
  {
    observe: {
      delivery: "owner",
      args_format: {
        type: "object",
        additionalProperties: false,
        required: ["every_ms"],
        properties: { every_ms: { type: "integer", minimum: 100 } },
      },
      legacy_trigger_type: "timer",
      onObserverAdded(obs) {
        const { every_ms } = argsOf(obs);
        // The engine does not check a legacy config against args_format: validate it here.
        if (!Number.isInteger(every_ms) || every_ms < 100) {
          throw new ObserveRejection(
            "INVALID_TIMER_CONFIG",
            "every_ms must be an integer of at least 100",
          );
        }
        // ... index the observer as before
      },
      onObserverRemoved(obs) {
        // ... use argsOf(obs) here too
      },
    },
  },
);
```

When a `registerTrigger` arrives for type `timer` and no worker provides the `timer` trigger type
the old way, the engine turns the trigger into an observer of your function:

- The observer belongs to the worker that called `registerTrigger`; its id is the trigger id.
- It has no args and no filters, and `deliver: 'input'`: its target receives the event you emit,
  exactly as the old trigger handler received the fired payload.
- The trigger's metadata becomes the observer's metadata sidecar.
- Your hook sees `obs.legacy = { trigger_type, config }`. Validate the config as your old
  `TriggerHandler` did, then accept or reject it like any observer. The old worker receives one
  `TriggerRegistrationResult` with the outcome, your rejection included.
- `unregisterTrigger` (or `engine::unregister_trigger`) disposes the observer.

The engine looks for the stand-in function where `registerTrigger` looks for a provider: only in the
trigger's `trigger_namespace` when it names one, otherwise in the registering worker's namespace and
then in `default`. Your worker must run a 0.25 SDK. A worker that still registers the trigger type
the old way always wins for new registrations, so stop calling `registerTriggerType` for the type in
the same release that adds the function.

## Against an older engine

Against an engine older than 0.25, a function with an `observe` descriptor registers as a plain
function: its hooks never run, and the SDK logs one warning. Local dispatch also stays off, and
every call goes through the engine as before.
