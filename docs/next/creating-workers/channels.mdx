Channels move large or binary payloads between iii workers outside the JSON function payload. Use a
channel for files, images, datasets, payloads above the JSON message limit, audio or video streams,
or progress updates during long-running work. For small JSON, use a regular `worker.trigger(...)`
call.

<Note>
  For how channels work (refs, lifecycle, and ownership), see
  [Channels](../understanding-iii/channels).
</Note>

## Payload size

The limit applies to the complete serialized UTF-8 JSON envelope, measured in bytes. The Rust, Node,
Python, and Go SDKs support messages up to **64 MiB**. The browser SDK has a **16 MiB** outbound
limit and does not fragment messages because browser WebSocket APIs do not expose frame control.
Browser workers also have a **16 MiB** receive limit.

For Rust, Node, Python, and Go, messages up to **16 MiB** are sent as one text frame. Larger
messages, up to and including 64 MiB, are sent as one fragmented WebSocket text message using
multiple frames. The engine sends every message larger than **1 MiB** to a worker as one fragmented
text message of 1 MiB frames, so no frame it sends exceeds a worker's frame size limit. Applications
send and receive these messages through the usual function APIs.

The receiving worker must run SDK version **0.24.5 or later** to accept messages larger than 16 MiB.
An updated engine checks the serialized envelope against the target worker's receive limit and
returns `payload_too_large` to the caller when the target cannot accept it. The engine sets that
limit when the worker registers:

- A browser worker gets **16 MiB**.
- A worker that declares the `large-messages.v1` protocol feature gets **64 MiB**, whatever version
  it reports. The Rust, Node, Python, and Go SDKs declare it from 0.25.0; the browser SDK does not.
- Any other worker gets **64 MiB** when the version it reports is an SDK version of 0.24.5 or later,
  written as semver (`0.24.6`, `0.25.0-rc.5`) or PEP 440 (`0.25.0rc5`, `0.24.5.post1`). It gets **16
  MiB** when the version is missing, cannot be parsed, or is older, including pre-releases of
  0.24.5. Other features, such as `observe.v1`, do not count.

SDK 0.24.5 through 0.25.0-rc.5 do not declare `large-messages.v1`, so the engine relies on the
version they report. A Rust worker on one of them that sets `WorkerMetadata.version` to its own
version instead of the SDK version therefore stays at 16 MiB. Upgrade it to SDK 0.25.0 or later.

Above **64 MiB**, the Rust, Node, Python, and Go SDKs reject the message locally with
`payload_too_large`; the error message links to this [Payload size](#payload-size) section. Engines
older than the updated size check forward messages as a single frame without checking the target's
limit. An older worker may then disconnect if the message is too large for it. Use an engine and
SDKs from the same release, or newer.

The engine reads up to **64 MiB** per message from a worker, whether the message arrives as one
frame or as fragments, so it also accepts the single large frames of SDKs older than 0.24.5. When a
worker sends a larger message, the engine drops it and the connection stays open. A call gets
`payload_too_large` as its result, and when a function returns a result that is too large, its
caller gets `payload_too_large` instead. Other calls on the connection are not affected. A message
the engine cannot answer, such as a call that expects no result, is dropped and logged.

Observer activations follow the same limits, and the engine keeps at most **64 MiB** of one observed
event (every field its observers capture, input and output counted separately). An event over either
limit is not delivered: the observer counts a `TOO_LARGE` drop and the engine logs a warning. See
[Observers / Event size](../using-iii/observers#event-size).

Use a channel for payloads above **64 MiB**. Channels stream payload bytes separately from the JSON
function envelope. Channel data uses a separate WebSocket connection, and the SDK splits each write
into 64 KiB frames. See [Using channels](#using-channels).

## Using channels

The subsections below use the local ends of one channel. They create a channel, write to its
`writer`, and read from its `reader`.

### Create a channel

`createChannel(worker)` from `iii-sdk/helpers` returns a channel with two local ends and two
serializable refs. In Python, use `create_channel_async(worker)` from `iii.helpers`. In Rust, use
`iii_sdk::helpers::create_channel(&worker, None)`. `writer` and `reader` are the local stream ends.
`writerRef` and `readerRef` (`writer_ref` and `reader_ref` in Python and Rust) are the tokens you
pass to another function so it can write or read the other end.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import { createChannel } from "iii-sdk/helpers";

    const channel = await createChannel(worker);

    // channel.writer
    // channel.reader
    // channel.writerRef
    // channel.readerRef
    ```

  </Tab>
  <Tab title="Python">
    ```python
    from iii.helpers import create_channel_async

    channel = await create_channel_async(worker)

    # channel.writer
    # channel.reader
    # channel.writer_ref
    # channel.reader_ref
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    let channel = iii_sdk::helpers::create_channel(&worker, None).await?;

    // channel.writer
    // channel.reader
    // channel.writer_ref
    // channel.reader_ref
    ```

  </Tab>
</Tabs>

### Write to a channel

Write the payload to the local `writer` and close it when finished. The bytes flow through the
engine to whichever worker holds the matching `reader`.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    channel.writer.stream.end(Buffer.from("file contents"));
    ```

  </Tab>
  <Tab title="Python">
    ```python
    await channel.writer.write(b"file contents")
    await channel.writer.close_async()
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    channel.writer.write(b"file contents").await?;
    channel.writer.close().await?;
    ```

  </Tab>
</Tabs>

### Read from a channel

Read the local `reader` until the other end closes. The bytes arrive in the order they were written
by whichever worker holds the matching `writer`. If the writer's connection ends without a close (it
aborted, crashed or lost its connection), the read fails with an error instead of ending: treat it
as an incomplete transfer. See
[Backpressure and lifecycle](../understanding-iii/channels#backpressure-and-lifecycle) for how a
writer aborts.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    let bytes = 0;
    for await (const chunk of channel.reader.stream) {
      bytes += Buffer.isBuffer(chunk) ? chunk.length : Buffer.byteLength(chunk);
    }
    ```

  </Tab>
  <Tab title="Python">
    ```python
    bytes_total = 0
    async for chunk in channel.reader:
        bytes_total += len(chunk)
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    let mut bytes = 0;
    while let Some(chunk) = channel.reader.next_binary().await? {
        bytes += chunk.len();
    }
    ```

  </Tab>
</Tabs>

### Send text messages

Use text messages for small updates, such as progress. Text messages go through the same channel as
the bytes.

- Node: send with `channel.writer.sendMessage(text)`. Receive with
  `channel.reader.onMessage(callback)`.
- Python: send with `await channel.writer.send_message_async(text)`. Receive with
  `channel.reader.on_message(callback)`.
- Rust: send with `channel.writer.send_message(&text).await?`. Receive with
  `channel.reader.on_message(callback).await`.

Register the callback first. Then read the reader as shown in
[Read from a channel](#read-from-a-channel). The SDK calls the callback for each text message that
arrives during the read.

## Using channels across functions

A channel is useful when two functions hold its two ends. One function keeps the local `writer` or
`reader`. The other function receives the matching ref in its payload. The next sections show how to
send a ref with a trigger call, and how the receiving function reads or writes with it.

### Pass a channel ref to another function

Pass the `readerRef` (or `writerRef`) as part of a normal function invocation. The receiving
function uses the ref to read from (or write to) the channel.

The receiving function reads until the writer closes. Do not wait for the result before you close
the writer. If you do, both sides wait until the call times out (after 30 seconds by default). A
channel holds only a small amount of data until the reader attaches. For large data, start the call
first. Then write the data, close the writer, and wait for the result. When you pass a `writerRef`,
read from the reader while the call runs. Wait for the result after the read ends.

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    const pending = worker.trigger({
      function_id: "files::process",
      payload: { filename: "report.csv", reader: channel.readerRef },
    });
    channel.writer.stream.end(Buffer.from("file contents"));
    const result = await pending;
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import asyncio

    pending = asyncio.create_task(worker.trigger_async({
        "function_id": "files::process",
        "payload": {"filename": "report.csv", "reader": channel.reader_ref.model_dump()},
    }))
    await channel.writer.write(b"file contents")
    await channel.writer.close_async()
    result = await pending
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::protocol::TriggerRequest;
    use serde_json::json;

    let call = worker.trigger(TriggerRequest {
        function_id: "files::process".to_string(),
        payload: json!({
            "filename": "report.csv",
            "reader": channel.reader_ref,
        }),
        action: None,
        timeout_ms: None,
    });
    let write = async {
        channel.writer.write(b"file contents").await?;
        channel.writer.close().await
    };
    let (result, written) = tokio::join!(call, write);
    written?;
    let result = result?;
    ```

  </Tab>
</Tabs>

Node and Python deserialize incoming channel refs into live `ChannelReader` / `ChannelWriter`
objects before the handler runs, so the ref arrives ready to iterate or write to. Rust receives the
ref in JSON and reconstructs the reader or writer explicitly with `ChannelReader::new(...)` or
`ChannelWriter::new(...)`.

<Warning>
  The channel belongs to the worker that created it. Keep that worker connected until the receiving
  function has attached to the ref. If the creator disconnects first, unattached ends are dropped.
  See [Channel ownership](../understanding-iii/channels#channel-ownership).
</Warning>

### Read from a channel ref

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import type { ChannelReader } from "iii-sdk/channel";

    worker.registerFunction("files::process", async (input: { reader: ChannelReader }) => {
      let bytes = 0;
      for await (const chunk of input.reader.stream) {
        bytes += Buffer.isBuffer(chunk) ? chunk.length : Buffer.byteLength(chunk);
      }
      return { bytes };
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    async def process_file(input: dict) -> dict:
        reader = input["reader"]
        total = 0
        async for chunk in reader:
            total += len(chunk)
        return {"bytes": total}

    worker.register_function("files::process", process_file)
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::channel::ChannelReader;
    use iii_sdk::helpers::{extract_channel_refs, ChannelDirection};
    use iii_sdk::{Error, RegisterFunction};
    use serde_json::{json, Value};

    worker.register_function(
        "files::process",
        RegisterFunction::new_async({
            let worker = worker.clone();
            move |input: Value| {
                let worker = worker.clone();
                async move {
                    let refs = extract_channel_refs(&input);
                    let (_, reader_ref) = refs
                        .iter()
                        .find(|(k, r)| k == "reader" && matches!(r.direction, ChannelDirection::Read))
                        .ok_or_else(|| Error::Handler("missing reader channel ref".into()))?;

                    let reader = ChannelReader::new(worker.address(), reader_ref);
                    let mut bytes = 0;
                    while let Some(chunk) = reader.next_binary().await? {
                        bytes += chunk.len();
                    }
                    Ok(json!({ "bytes": bytes }))
                }
            }
        }),
    );
    ```

  </Tab>
</Tabs>

### Write to a channel ref

<Tabs>
  <Tab title="Node / TypeScript">
    ```typescript
    import type { ChannelWriter } from "iii-sdk/channel";

    worker.registerFunction("files::generate", async (input: { writer: ChannelWriter }) => {
      input.writer.stream.write(Buffer.from("hello "));
      input.writer.stream.end(Buffer.from("world"));
      return { ok: true };
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    async def generate_file(input: dict) -> dict:
        writer = input["writer"]
        await writer.write(b"hello ")
        await writer.write(b"world")
        await writer.close_async()
        return {"ok": True}

    worker.register_function("files::generate", generate_file)
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::channel::ChannelWriter;
    use iii_sdk::helpers::{extract_channel_refs, ChannelDirection};
    use iii_sdk::{Error, RegisterFunction};
    use serde_json::{json, Value};

    worker.register_function(
        "files::generate",
        RegisterFunction::new_async({
            let worker = worker.clone();
            move |input: Value| {
                let worker = worker.clone();
                async move {
                    let refs = extract_channel_refs(&input);
                    let (_, writer_ref) = refs
                        .iter()
                        .find(|(k, r)| k == "writer" && matches!(r.direction, ChannelDirection::Write))
                        .ok_or_else(|| Error::Handler("missing writer channel ref".into()))?;

                    let writer = ChannelWriter::new(worker.address(), writer_ref);
                    writer.write(b"hello ").await?;
                    writer.write(b"world").await?;
                    writer.close().await?;
                    Ok(json!({ "ok": true }))
                }
            }
        }),
    );
    ```

  </Tab>
</Tabs>
