## Register a function

A worker registers a function with `worker.registerFunction(id, handler)`. Callers reach the
function by its `id` in the worker's namespace. For the steps in each SDK, see
[Creating Workers / Functions](../creating-workers/functions#register-a-function). The samples on
this page call the `math::add` function from that page. A worker registers it in the `orders`
namespace.

### Every function is observable

Any worker allowed to invoke a function can also observe it: `iii.observe` invokes another function
for each invocation that passes declarative filters, with no code in the observed function's worker.
A function can declare how it is observed, or refuse observers, with the `observe` option of
`registerFunction`. See [Observers](./observers) and
[Observable functions](../creating-workers/observable-functions).

## Triggering (Invoking) functions

A function runs when something calls it. A caller can be the CLI (`iii trigger`), worker code
(`worker.trigger`), or a trigger bound to an event source, such as the `http`, `cron`, `queue`, or
`state` worker. The handler code is the same for each caller.

The two most common ways to invoke a function directly are from worker code with `worker.trigger` or
from the terminal with the command `iii trigger`. The engine routes the call to whatever worker
registered the function; no trigger registration is involved. The `action` field controls delivery:
by default the call waits for the function to return its result, or for the configured timeout to
fire. Pass a different `TriggerAction` to change that. For what each action does, see
[`TriggerAction`](../reference/sdk-node#triggeraction) in the SDK reference. `TriggerAction.Enqueue`
needs the [queue](https://workers.iii.dev/workers/queue) worker.

The SDK samples run in the `orders` worker, so they leave out `namespace`.

<Tabs>
  <Tab title="CLI">
    ```bash
    iii trigger --namespace orders math::add a=2 b=3
    ```
  </Tab>
  <Tab title="Node / TypeScript">
    ```typescript
    import { TriggerAction } from "iii-sdk";

    const result = await worker.trigger({
      function_id: "math::add",
      payload: { a: 2, b: 3 },
      // action: TriggerAction.Void(), // fire-and-forget
      // action: TriggerAction.Enqueue({ queue: "math" }), // route through queue
    });
    ```

  </Tab>
  <Tab title="Python">
    ```python
    from iii import TriggerAction

    result = worker.trigger({
        "function_id": "math::add",
        "payload": {"a": 2, "b": 3},
        # "action": TriggerAction.Void(), # fire-and-forget
        # "action": TriggerAction.Enqueue(queue="math"), # route through queue
    })
    # result = await worker.trigger_async({...}) # awaitable form for asyncio callers
    ```

  </Tab>
  <Tab title="Rust">
    ```rust
    use iii_sdk::TriggerAction;
    use iii_sdk::protocol::TriggerRequest;
    use serde_json::json;

    let result = worker
        .trigger(TriggerRequest {
            function_id: "math::add".into(),
            payload: json!({ "a": 2, "b": 3 }),
            action: None,
            // action: Some(TriggerAction::Void),                                  // fire-and-forget
            // action: Some(TriggerAction::Enqueue { queue: "math".to_string() }), // route through queue
            timeout_ms: None,
        })
        .await?;
    ```

  </Tab>
  <Tab title="Go">
    ```go
    result, err := client.Trigger(ctx, iii.TriggerRequest{
        FunctionID: "math::add",
        Payload:    json.RawMessage(`{"a":2,"b":3}`),
        Namespace:  "default", // target a specific namespace
        // Action: iii.VoidAction(),          // fire-and-forget
        // Action: iii.EnqueueAction("math"), // route through queue
    })
    if err != nil {
        log.Fatal(err)
    }
    log.Printf("math::add returned %s", result)
    ```

  </Tab>
</Tabs>

<Note>
  A call to a function that the calling worker registered itself runs in-process once the engine
  confirmed the registration (local dispatch), with the same result, errors, and timeout as a call
  through the engine. Pass `dispatch: "remote"` (Python `"dispatch": "remote"`, Rust
  `.dispatch(Dispatch::Remote)`, Go `Dispatch: iii.DispatchRemote`) to send one call through the
  engine anyway. See [Local dispatch](./observers#local-dispatch).
</Note>

<Note>
  Bind a trigger to a function to run it on an event, such as an `http` request, a `cron` schedule,
  or a `state` change. See [Triggers / Register a trigger](./triggers#register-a-trigger). To run a
  function when another function is invoked, or on an engine event, see [Observers](./observers).
</Note>

<Note>
  In Python, `worker.trigger` and `worker.shutdown` block. Inside `asyncio`, use
  `worker.trigger_async` and `worker.shutdown_async`. For channels, use
  `create_channel_async(worker)` from `iii.helpers`. See the [Python SDK
  reference](../reference/sdk-python).
</Note>

### Routing to a namespace

A call resolves its function in one namespace. Set `namespace` on the call to pick that namespace.
Without `namespace`, the call resolves in the namespace of the calling worker. A call to an
`engine::*` or `configuration::*` function without `namespace` resolves in `default`. Without
`--namespace`, `iii trigger` uses the `III_NAMESPACE` value of the shell. When `III_NAMESPACE` is
not set, it uses `default`. For the steps and the errors, see
[Use namespaces](./namespaces#trigger-a-function-in-a-namespace).

## Trigger functions from the CLI

Pass `--help` after a function id to print the description and the request schema of the function:

```bash
iii trigger function::id --help
```

To add schemas when you register a function, see
[Creating Workers / Functions](../creating-workers/functions#attach-request-and-response-schemas).

`iii trigger` calls the real handler through the engine, the same as any other caller. A call to a
function that writes state or a database changes that data.

## Common functions

The workers below register functions that your project can call. Call them with
[`iii trigger`](./cli) or [`worker.trigger`](#triggering-invoking-functions).

### Engine functions (`engine::*`)

The `iii-engine-functions` worker registers the `engine::*` functions. This worker always runs. To
see the request schema of one function, run `iii trigger <function> --help`.

To list the connected workers, call `engine::workers::list`. To list the trigger types and the
registered triggers, call `engine::triggers::list` and `engine::registered-triggers::list`. To list
the registered functions, call `engine::functions::list`. To list, read, or remove observers, call
`engine::observers::list`, `engine::observers::get`, or `engine::observers::dispose`. See
[Inspect observers](./observers#inspect-observers). To run a function when a worker connects or
disconnects, or when the set of functions changes, bind it to the `engine::workers-available` or
`engine::functions-available` trigger type. For every function, its filters, and the trigger events,
see [Engine discovery functions](../reference/engine-protocol#engine-discovery-functions) and
[Engine discovery triggers](../reference/engine-protocol#engine-discovery-triggers).

From 0.25, observe the equivalent event sources instead: `engine::on-functions-changed` and
`engine::on-workers-changed`, with `deliver: "input"` so the target receives the same payload. See
[Engine-hosted event sources](./observers#engine-hosted-event-sources).

<Note>
  For the `engine::*` trigger types and functions, see the [iii-engine-functions worker
  docs](https://workers.iii.dev/workers/iii-engine-functions).
</Note>

### Common workers

Each of these workers registers its own functions. For function ids and payloads, see the docs of
each worker:

<Warning title="Deprecated">
  `iii-stream` is deprecated (iii-stream) and will be removed in an upcoming release. `pubsub` is
  deprecated (pubsub) and will be removed in an upcoming release. Behavior is unchanged for now. See
  [Migrate from iii-stream and pubsub](../upgrading/migrate-from-streams).
</Warning>

- **State**: key-value state, grouped by `scope`, with a `state` trigger type that fires when a key
  is created, updated, or deleted. A `scope` is separate from the
  [routing namespaces](../understanding-iii/namespaces). See
  [state](https://workers.iii.dev/workers/state).
- **Stream** (deprecated): real-time push to connected clients over WebSocket. See
  [iii-stream](https://workers.iii.dev/workers/iii-stream). For new work, use
  [worker-owned trigger types](../creating-workers/triggers#declaring-a-trigger-type) or
  [channels](../creating-workers/channels).
- **Queue**: durable job processing with retries, FIFO or concurrent delivery, concurrency limits,
  and a dead-letter queue. See [queue](https://workers.iii.dev/workers/queue).
- **Pub/Sub** (deprecated): topic fan-out with no durability guarantees. See
  [pubsub](https://workers.iii.dev/workers/pubsub). For new work, use worker-owned trigger types or
  durable queue topics.
- **Observability**: traces, logs, metrics, alerts, sampling rules, and rollups. See
  [iii-observability](https://workers.iii.dev/workers/iii-observability).
