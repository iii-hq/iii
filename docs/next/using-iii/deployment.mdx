This page shows how to run a iii project in production. For local development, see the
[Quickstart](../quickstart) and the [Engine](./engine) page.

## iii Cloud deployments

`iii cloud` manages hosted iii deployments. The iii CLI runs the separate `iii-cloud` binary for
these commands. If that binary is not installed, the iii CLI downloads it. Run `iii cloud --help` to
see the commands that your version supports.

<Note>iii's cloud will be available soon.</Note>

## Deploy with Docker

Generate the Docker assets with the CLI and start them with Docker Compose. Use
`iii project init --docker` for a fresh project, or `iii project generate-docker` to add Docker
assets to an existing one:

```bash
iii project generate-docker
```

Both forms emit three files at the project root: `Dockerfile`, `docker-compose.yml`, and `.env`.
Re-running the generator does not overwrite existing files, so edits you make to the templates
stick.

<Warning>
  The generated image starts only the engine, with `iii --config /app/config.yaml`. It does not
  start the workers in `worker-compose.yaml`. To run the workers, attach Compose to the engine in
  the container:

```bash
iii compose --engine ws://127.0.0.1:49134 --up --file /path/to/worker-compose.yaml
```

The `--engine` flag stops Compose from starting a second engine. For more about Compose, see
[Run a Compose project](#run-a-compose-project). The `Dockerfile` copies `config.yaml` from the
project root. If your project has no `config.yaml`, create one with the line `workers: []` before
you build.

</Warning>

Start the stack:

```bash
docker compose up -d
```

The generated `docker-compose.yml` maps these ports:

| Port  | Listener                                                  |
| ----- | --------------------------------------------------------- |
| 49134 | Engine WebSocket for trusted worker connections           |
| 3111  | `http` worker. The generated container does not start it. |
| 3112  | `iii-stream` worker, when `config.yaml` declares it       |
| 9464  | No listener at this release                               |

To keep the engine port private, change the mapping in `docker-compose.yml` to
`"127.0.0.1:49134:49134"`. If the `http` worker runs on the same host, remove the `3111:3111`
mapping from `docker-compose.yml`. Otherwise the worker cannot bind port 3111.

The `Dockerfile` builds from `iiidev/iii:latest`, a distroless image that runs as a non-root user.
`docker-compose.yml` has commented-out Redis and RabbitMQ services. Uncomment them when a worker
needs an external adapter.

## Run a Compose project

Compose runs in the foreground. Run it under a process supervisor, such as systemd. With `--up`,
Compose starts the engine from the `engine:` section. Compose also starts the workers under
`containers:`.

```bash
iii compose --namespace prod --up --file /path/to/worker-compose.yaml
```

To run Compose as a systemd service, create a unit file. This is a basic example:

```ini
[Unit]
Description=iii compose
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/iii compose --namespace prod --up --file /path/to/worker-compose.yaml
Restart=always

[Install]
WantedBy=multi-user.target
```

Change `/usr/local/bin/iii` to the path of the `iii` binary on your server.

<Warning>
  Use `Type=simple`. With `Type=notify`, systemd waits for an `sd_notify` readiness message. Compose
  does not send this message.
</Warning>

## Configure a reverse proxy

The `http` worker, `iii-stream`, and the rbac-proxy worker do not terminate TLS. Put a reverse proxy
in front of them. The proxy handles TLS and sends each host name to one port. Send each request path
to the listener unchanged. Do not add or remove a path prefix.

<Warning>
  The engine listener on `49134` is trusted. Any client that connects to it can register functions
  and call every function. Keep `49134` on a private network. Send public worker connections to the
  [rbac-proxy worker](https://workers.iii.dev/workers/rbac-proxy) port. Its default is `49200`. See
  [Workers](./workers).
</Warning>

### Caddy

```
ws.your-domain.com {
    reverse_proxy 127.0.0.1:49200
}

api.your-domain.com {
    reverse_proxy 127.0.0.1:3111
}

stream.your-domain.com {
    reverse_proxy 127.0.0.1:3112
}
```

<Note>
  This is only an example configuration. Refer to the [Caddy
  documentation](https://caddyserver.com/docs/) for full configuration.
</Note>

### Nginx

```nginx
server {
    listen 443 ssl;
    server_name ws.your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:49200;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

server {
    listen 443 ssl;
    server_name api.your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3111;
    }
}

server {
    listen 443 ssl;
    server_name stream.your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3112;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

<Note>
  This is only an example configuration. See the [Nginx documentation](https://nginx.org/en/docs/)
  for the full configuration such as SSL, header, and proxy options.
</Note>
