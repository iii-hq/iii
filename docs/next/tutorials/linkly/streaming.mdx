`iii-stream` is for **real-time data transmission**. It pushes data to a client the moment the data
changes, for example a live feed of clicks for a dashboard. Subscribers receive each change. Workers
write to a stream with `stream::set`. In this chapter you move the live broadcast into its own
`click-streamer` worker, so the `link` worker stays focused on links.

## Add the workers

`iii-stream` sends clicks to clients in Chapter 7. The `click-streamer` worker writes the clicks to
the stream. `iii-stream` ships with the engine. The scaffold's `worker-compose.yaml` already lists
it under `engine.workers`, so it runs from the start:

```yaml worker-compose.yaml
engine:
  url: ws://127.0.0.1:49134
  workers:
    iii-stream: {}
```

You only enable the `click-streamer` container here. Uncomment the Ch. 5 block under `containers`:

```yaml worker-compose.yaml
click-streamer:
  worker: path://./click-streamer
  start_after: [pubsub]
```

## Broadcast clicks in real time

Have `link` announce each click with a `pubsub` event. Then, have `click-streamer` push the event
onto the live feed.

### Add a `link.clicked` event to the `link` worker

First, publish a `link.clicked` event from `link::record_click`. In `link/src/index.ts`, comment out
the `Ch. 3 | link::record_click` block. Then uncomment the `Ch. 5 | link::record_click` block that
replaces it. For more information, see
[The worker entry point](./foundations#the-worker-entry-point).

```typescript link/src/index.ts {12-16}
worker.registerFunction(
  "link::record_click",
  async (payload: { code: string; clicked_at: string }) => {
    await worker.trigger({
      function_id: "database::execute",
      payload: {
        db: DB,
        sql: "INSERT INTO clicks (code, clicked_at) VALUES (?, ?)",
        params: [payload.code, payload.clicked_at],
      },
    });
    worker.trigger({
      function_id: "publish",
      payload: { topic: "link.clicked", data: payload },
      action: TriggerAction.Void(),
    });
    return { recorded: true };
  },
);
```

<Info>
  The new `publish` call has no `await`, and its `action` is `TriggerAction.Void()`. The SDK sends
  the call and does not wait for a result. Use this for calls such as `publish`, where you do not
  need a result or a confirmation that the call ran.
</Info>

### Set up the `click-streamer` worker

Now set up the `click-streamer` worker. It subscribes to `link.clicked` and broadcasts each click to
a `clicks` stream with `stream::set`. A `stream::set` call stores the item. It also pushes the item
to each WebSocket subscriber of that stream and group. It also runs each `stream` trigger that
matches the stream and group. Chapter 7 uses a `stream` trigger. Uncomment the Ch. 5 block in
`click-streamer/src/index.ts`:

```typescript click-streamer/src/index.ts
import { registerWorker } from "iii-sdk";
import { Logger } from "@iii-dev/helpers/observability";

const worker = registerWorker(process.env.III_URL ?? "ws://localhost:49134", {
  workerName: "click-streamer",
});
const logger = new Logger();

worker.registerFunction(
  "click-streamer::broadcast",
  async (data: { code: string; clicked_at: string }) => {
    await worker.trigger({
      function_id: "stream::set",
      payload: {
        stream_name: "clicks",
        group_id: "all",
        item_id: `${data.code}-${data.clicked_at}`,
        data,
      },
    });
    return { streamed: true };
  },
);

worker.registerTrigger({
  type: "subscribe",
  function_id: "click-streamer::broadcast",
  config: { topic: "link.clicked" },
});

logger.info("click-streamer ready");
```

Restart Compose so it picks up the change:

```bash
iii trigger compose::restart
```

The browser you build in Chapter 7 subscribes to `clicks`/`all` and counts those broadcasts live.

## See it work

With the engine running, create a few links and follow each:

```bash
for n in $(seq 4 6); do
  curl -s -X POST http://127.0.0.1:3111/links \
    -H 'Content-Type: application/json' -d "{\"url\":\"https://iii.dev\",\"code\":\"iii-example-$n\"}"
  curl -s -o /dev/null "http://127.0.0.1:3111/s/iii-example-$n"
done
```

Then read the live `clicks` stream:

```bash
iii trigger stream::list stream_name=clicks group_id=all
```

The output lists one item for each click. Your `clicked_at` values differ:

```json
[
  {
    "clicked_at": "2026-05-27T10:00:00.000Z",
    "code": "iii-example-4"
  },
  {
    "clicked_at": "2026-05-27T10:00:00.120Z",
    "code": "iii-example-5"
  },
  {
    "clicked_at": "2026-05-27T10:00:00.240Z",
    "code": "iii-example-6"
  }
]
```

Each redirect lands in the stream as the `click-streamer` worker broadcasts it.
