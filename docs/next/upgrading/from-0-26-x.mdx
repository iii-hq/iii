description:
  "The TypeScript, Python, and Rust SDKs replace the Channels API with streams in call payloads and
  results. Move each worker's channel code when you upgrade its SDK."

iii 0.27 changes the TypeScript (Node), Python, and Rust SDKs. Streaming between functions no longer
has an API of its own: a stream is a value of a call. Put a file, a readable, or a generator in a
payload or a result, and the function on the other side receives an `InputStream` to read; put a
writable or a file to create there, and it receives an `OutputStream` to write.

- **The Channels API is removed from the TypeScript, Python, and Rust SDKs.** `createChannel`,
  `ChannelReader`, `ChannelWriter`, `readerRef`, and `writerRef` (Python `create_channel`,
  `create_channel_async`, `reader_ref`, `writer_ref`; Rust `iii_sdk::helpers::create_channel` and
  `iii_sdk::channel::*`) give way to `InputStream` and `OutputStream`, and to `iii.pipe()` for an
  explicit pipe. This is a breaking change with no deprecated aliases.
- **The wire is unchanged.** A 0.26 engine serves 0.27 SDKs, and a ref has the same JSON in every
  SDK, so workers on 0.26 and 0.27 SDKs work together in one project. The 0.27 engine changes only
  the text of its `payload_too_large` errors.
- **Go and the browser SDK keep the channel API in 0.27.** Their `payload_too_large` error now links
  to [Streaming / Payload size](../creating-workers/streaming#payload-size).

## Before you upgrade

### Who needs to migrate

Only the workers whose SDK you upgrade to 0.27, and in them only the code that uses channels. A
project that keeps its SDKs on 0.26 needs no change, an engine upgrade alone changes nothing for
streaming, and you can move one worker at a time.

### Compatibility

| SDK                                      | On a 0.26 engine                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **0.26 SDK**                             | Unchanged.                                                                                                                                                  |
| **0.27 TypeScript, Python, or Rust SDK** | Everything works. Streams use `engine::channels::create` and the `/ws/channels` sockets, which the 0.26 engine already serves: no engine upgrade is needed. |
| **0.27 Go or browser SDK**               | Unchanged: both keep the channel API.                                                                                                                       |

### Mixed fleets

A ref is the same JSON whichever SDK sent it, so a stream crosses SDK versions. What the receiving
worker gets depends on its SDK:

| A stream or a ref sent | Reaches a 0.27 TypeScript, Python, or Rust worker as | Reaches a 0.26 TypeScript or Python worker, or a browser worker, as | Reaches a Go or 0.26 Rust worker as |
| ---------------------- | ---------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------- |
| in a call payload      | an `InputStream` or an `OutputStream`                | a `ChannelReader` or a `ChannelWriter`                              | the ref JSON                        |
| in a function's result | an `InputStream` or an `OutputStream`                | the ref JSON                                                        | the ref JSON                        |

The 0.27 lifecycle rules apply on the 0.27 side only. A handler on a 0.26 SDK that receives a writer
still has to close it, and a 0.27 caller that passed it a sink waits until it does: its call
resolves only after the sink has received the whole stream. If the 0.26 handler never opens the
writer, the call fails with `TIMEOUT` when its timeout expires, and the SDK aborts the sink.

A 0.26 TypeScript or Python writer that closes without writing anything never opens its socket, so
its reader, on any SDK version, waits until the engine expires the pipe. This is 0.26 behavior: a
0.27 writer opens the socket to close it, so its reader sees an empty stream at once. Upgrade the
writing side to fix it.

### Find what to change

Search each worker for the removed APIs. A few hits, such as `sendMessage` on another library's
socket, may be unrelated:

```bash
# TypeScript and JavaScript
git grep -nE 'createChannel|ChannelReader|ChannelWriter|readerRef|writerRef|iii-sdk/channel|extractChannelRefs|isChannelRef|StreamChannelRef|ChannelDirection|ChannelItem|sendMessage|onMessage|\.(reader|writer|request_body|response)\.stream' -- '*.ts' '*.tsx' '*.js' '*.mjs' '*.cjs'

# Python
git grep -nE 'create_channel|ChannelReader|ChannelWriter|reader_ref|writer_ref|iii\.channel|extract_channel_refs|is_channel_ref|StreamChannelRef|ChannelDirection|ChannelItem|send_message|on_message|close_async' -- '*.py'

# Rust
git grep -nE 'create_channel|ChannelReader|ChannelWriter|reader_ref|writer_ref|iii_sdk::channel|extract_channel_refs|is_channel_ref|StreamChannelRef|ChannelDirection|ChannelItem|send_message|on_message' -- '*.rs'
```

Then work through the sections below:

1. [Send a stream](#send-a-stream) where a caller creates a channel and passes its `readerRef`.
2. [Return a stream](#return-a-stream) or
   [write into the caller's sink](#write-into-the-callers-sink) where a caller creates a channel and
   passes its `writerRef`.
3. [HTTP `request_body` and `response`](#http-request_body-and-response) in route handlers that
   stream.
4. [Messages](#messages) where code calls `sendMessage` or `onMessage`.
5. [Abort](#abort) where a writer destroys its stream or is dropped on failure.
6. [Ref helpers](#ref-helpers-move-to-the-protocol-module) where code finds refs by hand.
7. [`createChannel` to `iii.pipe()`](#createchannel-to-iiipipe) where a pipe has to exist before its
   data.
8. Check the [behavior changes](#behavior-changes) and the [checklist](#checklist).

## What changed

| 0.26                                                                                                                                      | 0.27                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| TypeScript: `createChannel(worker, bufferSize?)` from `iii-sdk/helpers`                                                                   | a source or a sink in the payload, or `worker.pipe({ bufferSize })`                                |
| TypeScript: `Channel`, `ChannelReader`, `ChannelWriter`, and the `iii-sdk/channel` subpath                                                | `InputStream` and `OutputStream` from `iii-sdk`                                                    |
| TypeScript: `channel.readerRef`, `channel.writerRef` in a payload                                                                         | the stream itself in the payload: a source, a sink, `pipe.input`, or `pipe.output`                 |
| TypeScript: `reader.stream` (a Node `Readable`), `reader.readAll()`                                                                       | iterate the `InputStream`, `await input.bytes()`, or `input.toReadable()`                          |
| TypeScript: `writer.stream.write(chunk)`, `writer.stream.end()`, `writer.close()`                                                         | `await output.write(chunk)`, `await output.close()`, or `output.toWritable()`                      |
| TypeScript: `writer.sendMessage(text)`, `reader.onMessage(callback)`                                                                      | `await output.send(value)`, `for await (const msg of input.messages())`                            |
| TypeScript: `writer.stream.destroy()`                                                                                                     | `await output.abort(reason)`, or throw from the handler                                            |
| TypeScript: `extractChannelRefs`, `isChannelRef`, `ChannelDirection`, `ChannelItem` from `iii-sdk/helpers`                                | the same names from `iii-sdk/protocol`, with `StreamChannelRef`                                    |
| Python: `create_channel(worker)`, `create_channel_async(worker)` from `iii.helpers`                                                       | a source or a sink in the payload, or `worker.pipe()`, `await worker.pipe_async()`                 |
| Python: `Channel`, `ChannelReader`, `ChannelWriter` from `iii`, `iii.helpers`, and `iii.channel`                                          | `InputStream` and `OutputStream` from `iii`                                                        |
| Python: `channel.reader_ref.model_dump()`, `channel.writer_ref.model_dump()` in a payload                                                 | the stream itself in the payload                                                                   |
| Python: `await writer.write(data)`, `writer.close()`, `await writer.close_async()`                                                        | `await output.write(data)`, `await output.close()`                                                 |
| Python: `writer.send_message(text)`, `await writer.send_message_async(text)`, `reader.on_message(callback)`                               | `await output.send(value)`, `async for msg in input.messages()`                                    |
| Python: `async for chunk in reader`, `await reader.read_all()`                                                                            | the same on an `InputStream`                                                                       |
| Python: `extract_channel_refs`, `is_channel_ref`, `ChannelDirection`, `ChannelItem`, `StreamChannelRef`                                   | the same names from `iii.protocol`                                                                 |
| Rust: `iii_sdk::helpers::create_channel(&worker, buffer_size)`                                                                            | a source or a sink in the payload, or `worker.pipe().await?`                                       |
| Rust: `iii_sdk::channel::{Channel, ChannelReader, ChannelWriter}`, `ChannelReader::new(&address, &r)`, `ChannelWriter::new(&address, &r)` | `InputStream` and `OutputStream` fields in your input and output types, from `iii_sdk`             |
| Rust: `writer.send_message(&text)`, `reader.on_message(callback)`                                                                         | `output.send(&value).await`, `input.messages::<T>()`                                               |
| Rust: drop the writer without `close()` to abort                                                                                          | `output.abort(reason).await`, or return `Err` from the handler                                     |
| Rust: `iii_sdk::helpers::{extract_channel_refs, is_channel_ref, ChannelDirection, ChannelItem}`, `iii_sdk::channel::StreamChannelRef`     | the same names from `iii_sdk::protocol`                                                            |
| an abort on read: Node stream `'error'`, Python `ConnectionError`, Rust `Err`                                                             | `StreamAbortedError` (TypeScript, Python) and `Error::StreamAborted` (Rust), code `STREAM_ABORTED` |

The SDK also detects streams in what it sends and turns refs back into streams in what it receives,
in handler input and, new in 0.27, in call results. See [Streaming](../creating-workers/streaming)
for the full API.

## Send a stream

Put the source in the payload. The SDK creates the pipe, sends the ref, and pumps the data while the
call runs, so the caller no longer writes a channel next to the call. The handler reads the field
the same way as before, without `.stream` in TypeScript. The payload field keeps its name: it is
your function's contract.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    import { createReadStream } from "node:fs";
    import type { ChannelReader } from "iii-sdk/channel";
    import { createChannel } from "iii-sdk/helpers";

    // Caller
    const channel = await createChannel(worker);
    createReadStream("report.csv").pipe(channel.writer.stream);
    const result = await worker.call({
      function_id: "files::process",
      payload: { filename: "report.csv", reader: channel.readerRef },
    });

    // Handler
    worker.registerFunction("files::process", async (input: { reader: ChannelReader }) => {
      let bytes = 0;
      for await (const chunk of input.reader.stream) bytes += chunk.length;
      return { bytes };
    });
    ```

    **After (0.27)**

    ```typescript
    import { createReadStream } from "node:fs";
    import type { InputStream } from "iii-sdk";

    // Caller
    const result = await worker.call({
      function_id: "files::process",
      payload: { filename: "report.csv", reader: createReadStream("report.csv") },
    });

    // Handler
    worker.registerFunction("files::process", async (input: { reader: InputStream }) => {
      let bytes = 0;
      for await (const chunk of input.reader) bytes += chunk.length;
      return { bytes };
    });
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**

    ```python
    import asyncio

    from iii.helpers import create_channel_async

    # Caller: write the channel while the call reads it
    channel = await create_channel_async(worker)


    async def upload() -> None:
        with open("report.csv", "rb") as f:
            while chunk := f.read(64 * 1024):
                await channel.writer.write(chunk)
        await channel.writer.close_async()


    _, result = await asyncio.gather(
        upload(),
        worker.call_async(
            {
                "function_id": "files::process",
                "payload": {"filename": "report.csv", "reader": channel.reader_ref.model_dump()},
            }
        ),
    )


    # Handler
    async def process(payload: dict) -> dict:
        total = 0
        async for chunk in payload["reader"]:
            total += len(chunk)
        return {"bytes": total}
    ```

    **After (0.27)**

    ```python
    from iii import InputStream

    # Caller
    result = await worker.call_async(
        {
            "function_id": "files::process",
            "payload": {"filename": "report.csv", "reader": InputStream.from_file("report.csv")},
        }
    )


    # Handler: unchanged, payload["reader"] is an InputStream
    async def process(payload: dict) -> dict:
        reader: InputStream = payload["reader"]
        total = 0
        async for chunk in reader:
            total += len(chunk)
        return {"bytes": total}
    ```

  </Tab>
  <Tab title="Rust">
    **Before (0.26)**

    ```rust
    use iii_sdk::channel::ChannelReader;
    use iii_sdk::helpers::{create_channel, extract_channel_refs, ChannelDirection};

    // Caller: write the channel while the call reads it
    let data = tokio::fs::read("report.csv").await?;
    let channel = create_channel(&worker, None).await?;
    let upload = async {
        channel.writer.write(&data).await?;
        channel.writer.close().await
    };
    let call = worker.call(CallRequest::new(
        "files::process",
        json!({ "filename": "report.csv", "reader": channel.reader_ref }),
    ));
    let (_, result) = tokio::try_join!(upload, call)?;

    // Handler: find the ref by hand and open it with the engine address
    let address = worker.address().to_string();
    worker.register_function(
        "files::process",
        RegisterFunction::new_async(move |input: Value| {
            let address = address.clone();
            async move {
                let refs = extract_channel_refs(&input);
                let (_, reader_ref) = refs
                    .iter()
                    .find(|(key, r)| key == "reader" && matches!(r.direction, ChannelDirection::Read))
                    .ok_or_else(|| Error::Handler("missing reader channel ref".into()))?;
                let bytes = ChannelReader::new(&address, reader_ref).read_all().await?.len();
                Ok(json!({ "bytes": bytes }))
            }
        }),
    );
    ```

    **After (0.27)**

    ```rust
    use iii_sdk::InputStream;
    use tokio::fs::File;

    // Caller
    let result = worker
        .call(CallRequest::new(
            "files::process",
            json!({
                "filename": "report.csv",
                "reader": InputStream::from_reader(File::open("report.csv").await?),
            }),
        ))
        .await?;

    // Handler: a typed field, no ref lookup and no engine address
    #[derive(Deserialize, JsonSchema)]
    struct Upload {
        reader: InputStream,
    }

    worker.register_function(
        "files::process",
        RegisterFunction::new_async(|upload: Upload| async move {
            let bytes = upload.reader.read_all().await?.len();
            Ok::<_, Error>(json!({ "bytes": bytes }))
        }),
    );
    ```

## Return a stream

In 0.26, refs in a result were not turned into readers, so a function that produced a stream needed
its caller to create a channel and pass a `writerRef` in. In 0.27 the function returns the stream
and the caller reads it from the result. The caller no longer passes a writer, so this changes the
function's payload: move its callers in the same change. When the caller has a place for the bytes,
such as a file, [pass a sink](#write-into-the-callers-sink) instead.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    import { once } from "node:events";
    import type { ChannelWriter } from "iii-sdk/channel";
    import { createChannel } from "iii-sdk/helpers";

    // Caller: create the channel and pass the writer ref in
    const channel = await createChannel(worker);
    const done = worker.call({
      function_id: "reports::export",
      payload: { report_id: "r-42", writer: channel.writerRef },
    });
    done.catch(() => {});
    for await (const chunk of channel.reader.stream) render(chunk);
    await done;

    // Handler: write into the caller's channel
    worker.registerFunction(
      "reports::export",
      async (input: { report_id: string; writer: ChannelWriter }) => {
        for await (const row of db.rows(input.report_id)) {
          if (!input.writer.stream.write(`${row.id},${row.total}\n`)) {
            await once(input.writer.stream, "drain");
          }
        }
        input.writer.stream.end();
        return { ok: true };
      },
    );
    ```

    **After (0.27)**

    ```typescript
    import type { InputStream } from "iii-sdk";

    async function* csvLines(reportId: string) {
      for await (const row of db.rows(reportId)) yield `${row.id},${row.total}\n`;
    }

    // Handler: return the stream
    worker.registerFunction("reports::export", async (input: { report_id: string }) => ({
      csv: csvLines(input.report_id),
    }));

    // Caller: the field arrives as an InputStream
    const { csv }: { csv: InputStream } = await worker.call({
      function_id: "reports::export",
      payload: { report_id: "r-42" },
    });
    for await (const line of csv.lines()) render(line);
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**

    ```python
    import asyncio

    from iii.helpers import create_channel_async

    # Caller: create the channel and pass the writer ref in
    channel = await create_channel_async(worker)
    call = asyncio.create_task(
        worker.call_async(
            {
                "function_id": "reports::export",
                "payload": {"report_id": "r-42", "writer": channel.writer_ref.model_dump()},
            }
        )
    )
    async for chunk in channel.reader:
        render(chunk)
    await call


    # Handler: write into the caller's channel
    async def export(payload: dict) -> dict:
        writer = payload["writer"]
        async for row in db.rows(payload["report_id"]):
            await writer.write(f"{row.id},{row.total}\n".encode())
        await writer.close_async()
        return {"ok": True}
    ```

    **After (0.27)**

    ```python
    async def csv_lines(report_id: str):
        async for row in db.rows(report_id):
            yield f"{row.id},{row.total}\n".encode()


    # Handler: return the stream
    async def export(payload: dict) -> dict:
        return {"csv": csv_lines(payload["report_id"])}


    # Caller: the field arrives as an InputStream
    result = await worker.call_async(
        {"function_id": "reports::export", "payload": {"report_id": "r-42"}}
    )
    async for line in result["csv"].lines():
        render(line)
    ```

  </Tab>
  <Tab title="Rust">
    **Before (0.26)**

    ```rust
    use iii_sdk::helpers::create_channel;

    // Caller: create the channel, pass the writer ref in, read the other end
    let channel = create_channel(&worker, None).await?;
    let call = worker.call(CallRequest::new(
        "reports::export",
        json!({ "report_id": "r-42", "writer": channel.writer_ref }),
    ```

    **After (0.27)**

    ```rust
    }

        "reports::export",

            let lines = db
                .rows(req.report_id)
                .map_ok(|row| Bytes::from(format!("{},{}\n", row.id, row.total)));

    let csv = export.csv.read_all().await?;
    ```

## Write into the caller's sink

When the caller copied the reader end of its channel into a file or another writable, pass that sink
in the payload instead. The handler receives an `OutputStream`, and the caller's call resolves once
the sink has received everything.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    import { createWriteStream } from "node:fs";
    import { pipeline } from "node:stream/promises";
    import type { ChannelWriter } from "iii-sdk/channel";
    import { createChannel } from "iii-sdk/helpers";

    // Caller: pass the writer ref, copy the reader end into the file
    const channel = await createChannel(worker);
    await Promise.all([
      worker.call({
        function_id: "reports::render-pdf",
        payload: { report_id: "r-42", out: channel.writerRef },
      }),
      pipeline(channel.reader.stream, createWriteStream("r-42.pdf")),
    ]);

    // Handler
    worker.registerFunction(
      "reports::render-pdf",
      async (input: { report_id: string; out: ChannelWriter }) => {
        for await (const page of renderPages(input.report_id)) input.out.stream.write(page);
        input.out.stream.end();
      },
    );
    ```

    **After (0.27)**

    ```typescript
    import { createWriteStream } from "node:fs";
    import type { OutputStream } from "iii-sdk";

    // Caller: pass the file; the call resolves once it is written
    await worker.call({
      function_id: "reports::render-pdf",
      payload: { report_id: "r-42", out: createWriteStream("r-42.pdf") },
    });

    // Handler: returning closes `out`, throwing aborts it
    worker.registerFunction(
      "reports::render-pdf",
      async (input: { report_id: string; out: OutputStream }) => {
        for await (const page of renderPages(input.report_id)) await input.out.write(page);
      },
    );
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**

    ```python
    import asyncio

    from iii.helpers import create_channel_async

    # Caller: pass the writer ref, copy the reader end into the file
    channel = await create_channel_async(worker)


    async def save() -> None:
        with open("r-42.pdf", "wb") as f:
            async for chunk in channel.reader:
                f.write(chunk)


    await asyncio.gather(
        worker.call_async(
            {
                "function_id": "reports::render-pdf",
                "payload": {"report_id": "r-42", "out": channel.writer_ref.model_dump()},
            }
        ),
        save(),
    )


    # Handler
    async def render_pdf(payload: dict) -> None:
        out = payload["out"]
        async for page in render_pages(payload["report_id"]):
            await out.write(page)
        await out.close_async()
    ```

    **After (0.27)**

    ```python
    from iii import OutputStream

    # Caller: pass the file; the call resolves once it is written
    await worker.call_async(
        {
            "function_id": "reports::render-pdf",
            "payload": {"report_id": "r-42", "out": OutputStream.to_file("r-42.pdf")},
        }
    )


    # Handler: returning closes `out`, raising aborts it
    async def render_pdf(payload: dict) -> None:
        out: OutputStream = payload["out"]
        async for page in render_pages(payload["report_id"]):
            await out.write(page)
    ```

  </Tab>
  <Tab title="Rust">
    **Before (0.26)**

    ```rust
    use iii_sdk::helpers::create_channel;

    // Caller: pass the writer ref, copy the reader end into the file
    let channel = create_channel(&worker, None).await?;
    let call = worker.call(CallRequest::new(
        "reports::render-pdf",
        json!({ "report_id": "r-42", "out": channel.writer_ref }),

    let read = channel.reader.read_all();
    let (_, pdf) = tokio::try_join!(call, read)?;
    tokio::fs::write("r-42.pdf", pdf).await?;
    ```

    **After (0.27)**

    ```rust

    use tokio::fs::File;

    // Caller: pass the file; the call resolves once it is written
    worker
        .call(CallRequest::new(
            "reports::render-pdf",
            json!({
                "report_id": "r-42",
                "out": OutputStream::to_writer(File::create("r-42.pdf").await?),
            }),
        ))
        .await?;

    // Handler: Ok closes `out`, Err aborts it
    #[derive(Deserialize, JsonSchema)]
    struct RenderPdf {
        report_id: String,
        out: OutputStream,
    }

    worker.register_function(
        "reports::render-pdf",
        RegisterFunction::new_async(|req: RenderPdf| async move {
            for page in render_pages(&req.report_id).await? {
                req.out.write(&page).await?;
            }
            Ok::<_, Error>(())
        }),
    );
    ```

## HTTP `request_body` and `response`

The HTTP worker still passes a route's request body and response as refs in `request_body` and
`response`, and it reads the status and the headers from the same JSON messages. Only their SDK
types change: `request_body` is an `InputStream` and `response` is an `OutputStream`. The
`request_body` of the TypeScript `HttpRequest` and `StreamRequest` types and of the Python
`StreamRequest` is an `InputStream` too.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    import type { ChannelReader, ChannelWriter } from "iii-sdk/channel";

    type Echo = { request_body: ChannelReader; response: ChannelWriter };

    worker.registerFunction("files::echo", async ({ request_body, response }: Echo) => {
      response.sendMessage(JSON.stringify({ type: "set_status", status_code: 200 }));
      response.sendMessage(
        JSON.stringify({ type: "set_headers", headers: { "content-type": "text/plain" } }),
      );
      for await (const chunk of request_body.stream) response.stream.write(chunk);
      response.stream.end();
    });
    ```

    **After (0.27)**

    ```typescript
    import type { InputStream, OutputStream } from "iii-sdk";

    type Echo = { request_body: InputStream; response: OutputStream };

    worker.registerFunction("files::echo", async ({ request_body, response }: Echo) => {
      await response.send({ type: "set_status", status_code: 200 });
      await response.send({ type: "set_headers", headers: { "content-type": "text/plain" } });
      for await (const chunk of request_body) await response.write(chunk);
      // Returning closes the response.
    });
    ```

  <Tab title="Python">

    ```python
    import json
    ```

A route handler that returns a buffered response (`{ status_code, body }`) without touching
`response` needs no change: the HTTP worker calls a route through an observer, and in that case the
SDK leaves an untouched `response` alone when the handler returns a value.

### Streaming response helpers

The `StreamResponse` helpers (the `res` of the TypeScript `http()` wrapper and of the Python
`StreamResponse`) wrap the `OutputStream` now, and every method that writes is asynchronous:

| 0.26                                                              | 0.27                                                                             |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| TypeScript: `res.status(code)`, `res.headers(h)` returned nothing | `await res.status(code)`, `await res.headers(h)`                                 |
| TypeScript: `res.stream.write(chunk)`, `res.close()`              | `await res.write(chunk)`, `await res.close()` (`res.stream` stays, a `Writable`) |
| Python: `res.stream` (a writable wrapper), `res.close()`          | `await res.write(data)`, `await res.close()`; `res.stream` is removed            |
| Python: `res.writer` was a `ChannelWriter`                        | `res.writer` is the `OutputStream`                                               |

## Messages

`send` takes a value and sends it as JSON in one text frame, so drop your own `JSON.stringify` or
`json.dumps`. `messages()` parses each text frame, and yields a frame that is not JSON as its raw
string, so messages from a writer on a 0.26 SDK that sent plain text still arrive. A reader on a
0.26 SDK receives what `send` wrote as JSON text: a bare string arrives quoted.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    // Writer
    input.progress.sendMessage(JSON.stringify({ percent: 50 }));

    // Reader
    channel.reader.onMessage((msg) => update(JSON.parse(msg)));
    ```

    **After (0.27)**

    ```typescript
    // Writer
    await input.progress.send({ percent: 50 });

    // Reader
    for await (const msg of progress.messages<{ percent: number }>()) update(msg);
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**

    ```python
    # Writer
    await payload["progress"].send_message_async(json.dumps({"percent": 50}))

    # Reader
    channel.reader.on_message(lambda msg: update(json.loads(msg)))
    ```

    **After (0.27)**

    ```python
    # Writer
    await payload["progress"].send({"percent": 50})

    # Reader
    async for msg in progress.messages():
        update(msg)
    ```

  </Tab>
  <Tab title="Rust">
    **Before (0.26)**

    ```rust

    reader
        .on_message(|msg| {
            if let Ok(progress) = serde_json::from_str::<Progress>(&msg) {
                update(progress);
            }
        })
        .await;
    ```

    **After (0.27)**

    ```rust
    req.progress.send(&Progress { percent: 50 }).await?;

    // Reader
    let mut messages = progress.messages::<Progress>();
    while let Some(progress) = messages.try_next().await? {
        update(progress);
    }
    ```

  </Tab>
</Tabs>

A reader that needs both the bytes and the messages, in order, iterates `frames()`.

## Abort

In 0.26 each SDK aborted differently: Node with `writer.stream.destroy()` and no argument, Rust by
dropping the writer without `close()`, and Python had no abort call. In 0.27 the SDK aborts for you
in the common cases, and `abort(reason)` is one call everywhere:

- A source the SDK pumps (a generator, a readable, a file) that fails aborts its stream.
- A handler that throws aborts every received `OutputStream` it has written to.
- `await output.abort(reason)` aborts on purpose. If the stream's socket never opened, it opens it
  first, so the reader always learns of the failure.

A handler that throws before it touched a received `OutputStream` leaves that stream alone, as in
0.26: the caller learns of the failure from the call's error.

The reader gets a typed error after the data that was already sent.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript
    // Writer
    try {
      for await (const page of renderPages(id)) input.out.stream.write(page);
    } catch (err) {
      input.out.stream.destroy(); // no argument: destroy(err) crashes the worker
      throw err;
    }
    input.out.stream.end();

    // Reader: the stream emits 'error', so the loop throws
    for await (const chunk of channel.reader.stream) save(chunk);
    ```

    **After (0.27)**

    ```typescript
    import { StreamAbortedError } from "iii-sdk";

    // Writer: throwing aborts `out`; returning closes it
    for await (const page of renderPages(id)) await input.out.write(page);

    // Reader
    try {
      for await (const chunk of body) save(chunk);
    } catch (err) {
      if (err instanceof StreamAbortedError) discard(); // err.code is "STREAM_ABORTED"
      throw err;
    }
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**

    ```python
    # Writer: no abort call; a writer garbage-collected without close() aborts
    async for page in render_pages(report_id):
        await out.write(page)
    await out.close_async()

    # Reader
    try:
        async for chunk in channel.reader:
            save(chunk)
    except ConnectionError:
        discard()
        raise
    ```

    **After (0.27)**

    ```python
    from iii import StreamAbortedError

    # Writer: raising aborts `out`, returning closes it; out.abort(reason) aborts on purpose
    async for page in render_pages(report_id):
        await out.write(page)

    # Reader
    try:
        async for chunk in body:
            save(chunk)
    except StreamAbortedError:  # err.code is "STREAM_ABORTED"
        discard()
        raise
    ```

  </Tab>
  <Tab title="Rust">
    **Before (0.26)**

    ```rust
    // Writer: drop it without close() to abort
    for page in pages {
        if let Err(err) = writer.write(&page).await {
            drop(writer);
            return Err(err);
        }
    }
    writer.close().await?;
    ```

    **After (0.27)**

    ```rust

        req.out.write(&page).await?;
    }

    // Reader
    match body.read_all().await {
        Ok(data) => save(data),
        Err(err @ Error::StreamAborted { .. }) => {
            discard();
            return Err(err);
        }
        Err(err) => return Err(err),
    }
    ```

  </Tab>

The reader's `reason` is the engine's description of the close, such as
`channel writer aborted: closed with code 1011`: the engine does not relay the writer's own reason.
Report the cause in the call's error or result. A caller that passed a sink gets the abort as its
call's error, with the code `STREAM_ABORTED`, even when the function returned.

## Ref helpers move to the protocol module

The SDK now finds refs and turns them into streams, so most code that called `extractChannelRefs` or
`isChannelRef` can drop it. Code that still works with the raw ref JSON, such as a router that
inspects payloads, imports the helpers from the low-level protocol module:

| 0.26                                                                                                | 0.27                                                                                                 |
| --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `import { extractChannelRefs, isChannelRef, ChannelDirection, ChannelItem } from "iii-sdk/helpers"` | `import { extractChannelRefs, isChannelRef, ChannelDirection, ChannelItem } from "iii-sdk/protocol"` |
| `import type { StreamChannelRef } from "iii-sdk/channel"`                                           | `import type { StreamChannelRef } from "iii-sdk/protocol"`                                           |
| `from iii.helpers import extract_channel_refs, is_channel_ref, ChannelDirection, ChannelItem`       | `from iii.protocol import extract_channel_refs, is_channel_ref, ChannelDirection, ChannelItem`       |
| `from iii.channel import StreamChannelRef`                                                          | `from iii.protocol import StreamChannelRef`                                                          |
| `use iii_sdk::helpers::{extract_channel_refs, is_channel_ref, ChannelDirection, ChannelItem};`      | `use iii_sdk::protocol::{extract_channel_refs, is_channel_ref, ChannelDirection, ChannelItem};`      |
| `use iii_sdk::channel::StreamChannelRef;`                                                           | `use iii_sdk::protocol::StreamChannelRef;`                                                           |

The helpers see refs as JSON. A handler on a 0.27 SDK receives streams, not refs, so call them on
the raw JSON you hold, such as a value read from storage.

## `createChannel` to `iii.pipe()`

Most channels become a value in the payload or the result, as above. Keep an explicit pipe when the
stream has to exist before its data, when it goes to a call made later, or for a two-way session
(two pipes). `iii.pipe()` returns its two ends, `input` and `output`; put the end the other side
uses in the payload, where 0.26 code put a ref.

<Tabs>
  <Tab title="Node / TypeScript">
    **Before (0.26)**

    ```typescript

    const done = worker.call({
      function_id: "llm::complete",
      payload: { prompt, tokens: channel.writerRef },
    });
    channel.reader.onMessage((msg) => print(JSON.parse(msg).token));
    await channel.reader.readAll();
    await done;
    ```

    **After (0.27)**

    ```typescript

    const done = worker.call({
      function_id: "llm::complete",
      payload: { prompt, tokens: output },
    });
    done.catch(() => {});
    for await (const { token } of input.messages<{ token: string }>()) print(token);
    await done;
    ```

  </Tab>
  <Tab title="Python">
    **Before (0.26)**


    **After (0.27)**


  </Tab>
  <Tab title="Rust">

| 0.26 channel                     | 0.27 pipe                        |
| -------------------------------- | -------------------------------- |
| `channel.writer`                 | `pipe.output`, an `OutputStream` |
| `channel.reader`                 | `pipe.input`, an `InputStream`   |
| `channel.readerRef` in a payload | `pipe.input` in the payload      |
| `channel.writerRef` in a payload | `pipe.output` in the payload     |

The worker that calls `pipe()` owns the pipe, as with `createChannel`: keep it connected until the
other side has attached.

## Behavior changes

Beyond the renamed API, these rules are new for a worker on a 0.27 SDK:

- **A received `OutputStream` is closed when the handler returns, and aborted when it throws.** A
  0.26 handler that returned and kept writing in the background calls `keepOpen()` (Python and Rust
  `keep_open()`) first, and then closes or aborts the stream itself. A stream the handler never
  touched is closed as well when it returns, except in a call through an observer (an HTTP route,
  for example), where it is closed only when the handler returns nothing.
- **A received `InputStream` that the handler started reading and did not finish is cancelled when
  the handler returns.** Finish reading before returning.
- **Refs in call results arrive as streams.** In 0.26 a ref in a result stayed JSON. Code that read
  a ref out of a result and opened it now receives an `InputStream` or an `OutputStream` instead.
- **A stream has one reader.** A second read of the same `InputStream` fails; call `tee()` before
  the first read for copies in the same process.
- **Streams need a live call.** A call sent with `CallAction.Enqueue` and a stream or a ref anywhere
  in its payload is refused before it is sent, with the code `STREAM_NOT_ALLOWED`. Store the data
  and enqueue its key. `CallAction.Void` is allowed.
- **Observers receive `StreamInfo`.** When an observer captures the `input` or `output` of a call
  that carried a stream, its target receives `{ stream: true, direction, id }` in that field. A 0.26
  TypeScript or Python target got a live reader there, which raced the observed function for the
  bytes. See
  [Observe a call that carries a stream](../creating-workers/streaming#observe-a-call-that-carries-a-stream).
- **Rust streams bind lazily.** An `InputStream` or `OutputStream` decoded from JSON binds to the
  handler's worker inside a handler, and to the only client in the process elsewhere. A process with
  several clients calls `stream.bind(&worker)` before using a stream decoded outside a handler.
- **The `payload_too_large` error links to the new page:**
  `https://iii.dev/docs/creating-workers/streaming#payload-size`.

## Checklist

- [ ] Upgrade one worker's SDK at a time; workers on 0.26 SDKs, Go, and the browser keep working
      unchanged on the same engine
- [ ] Replace each `createChannel` / `create_channel` / `create_channel_async` whose writer feeds a
      call with the source itself in the payload
- [ ] Replace each `writerRef` / `writer_ref` passed in for a function to fill with a returned
      stream, or with a sink in the payload, and move that function's callers in the same change
- [ ] Type stream fields as `InputStream` and `OutputStream`; in Rust, replace
      `extract_channel_refs` and `ChannelReader::new` / `ChannelWriter::new` with typed struct
      fields
- [ ] Replace `reader.stream` and `writer.stream` with the stream itself, `write`, or the native
      bridges (`toReadable`, `toWritable`)
- [ ] Replace `sendMessage` / `send_message` with `send`, and `onMessage` / `on_message` with
      `messages()`, without your own JSON encoding
- [ ] Replace `writer.stream.destroy()` and dropping a Rust writer with `abort(reason)` or a throw,
      and catch `StreamAbortedError` (Rust `Error::StreamAborted`) where you caught the old errors
- [ ] Remove explicit closes the handler no longer needs, and call `keepOpen()` where a handler
      keeps writing after it returns
- [ ] Import `extractChannelRefs`, `isChannelRef`, `StreamChannelRef`, `ChannelDirection`, and
      `ChannelItem` from the protocol module
- [ ] Move calls queued with `CallAction.Enqueue` that carried a ref to stored data and a key
- [ ] Update observer targets that read a captured stream field to expect a `StreamInfo`
