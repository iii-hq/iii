the harness is inside the system.

the agent calls the same registry the system does. contracts get fetched, not memorized, so context comes from the engine on demand instead of being re-explained in the prompt every session.

pi's answer to context is engineering the prompt. iii's is the system answering questions on demand.

03 / 06

durable orchestration, not scripted turns.

register a trigger, end the turn, get woken. fan-out, fan-in, joins, and deadline wakes are primitives here, not something scripted around a chat loop.

pi ships no sub-agents and no background bash, on purpose. iii ships both because a system needs them.

reports::nightly
a cron trigger, registered once
worker.registerFunction("reports::nightly", async () => {
  await buildReport()
})

worker.registerTrigger({
  type: "cron",
  function_id: "reports::nightly",
  config: { expression: "0 6 * * *" },
})
 // the turn ends here.
 // the engine wakes reports::nightly at 06:00, every day
