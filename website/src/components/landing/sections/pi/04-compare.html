how you make it yours a TypeScript extension, skill, prompt template, theme create workers that register functions and triggers
language node / TypeScript, in-process any language, any runtime, interoperably: TS calling Python calling Rust
adding capability pi install npm:…, then /reload iii worker add, live, callable by every worker instantly
discovery files on disk, loaded at startup a live engine registry: register once, visible system-wide
sub-agents not built. tmux, or write an extension first-class: spawn, react, behave like any other worker
work after the turn ends turn-scoped. you script it engine-side triggers: cron, state changes, anything the system emits
observability session trees, /export, /share, tmux one trace across every worker, every language, every action executed
tool protocol no MCP by design: CLI tools plus READMEs functions with published schemas as the single contract
distribution npm or git packages of code a registry of running participants, as easy to install as a library
runs where your machine, one process docker, k8s, the edge, a browser tab, a raspberry pi, a microVM

extending a harness on iii means building new tools for that harness, and for the system underneath it. that's the more sustainable version of the same instinct.
