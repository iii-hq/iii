three primitives. the whole abstraction, in one screen.

every part of a system on iii — your services, your database, a nightly job, a browser tab, the agent itself — is described with the same three things. that's the abstraction, and it's why every part of an application interoperates with zero integration work.

never seen iii before? this is the entire vocabulary:

worker · hosts work

any process that connects to the engine: a python script, a node service, a rust binary, a browser tab, an HTTP API you already run — or the harness on this page. it connects and publishes what it can do.

function · does work

one named capability a worker exposes, with a typed schema — payments::charge::record. the id is the entire contract: a caller never learns where it runs or what language it's written in.

trigger · causes work

the reason a function runs: a schedule, a state change, an HTTP request, an event from another worker. it's registered engine-side, so it fires whether or not anyone — or any agent — is watching.

so nothing here needs glue. a function registered a second ago is already callable by every worker and every agent on the engine, and any trigger can cause it — no adapter, no client library per integration, no integration ticket. queues, sandboxes, sub-agents, observability, your business logic: all of it is these three, composed.
