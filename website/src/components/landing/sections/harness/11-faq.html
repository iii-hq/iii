questions. the ones a harness user actually asks.

is iii a harness?+

it does what a harness does, from the layer below. most harnesses solve one slice — a chat loop, a tool sandbox, a chained workflow. iii is the runtime the whole system already runs on, built on three engine primitives: worker, function, trigger.

the iii engine primitives
think of it like React's component model, but for traditional and agentic services. a minimal, common mental model for building systems — less cognitive complexity, fewer tokens, easier to reason about and scale.
protocol
allows any runtime, language, process, endpoint, browser, or device to become a worker and expose its functions and reactive triggers through the same typed interface.
live system surface
as workers connect, their functions and triggers become part of a live, typed catalog that the rest of the system can immediately discover and use. developers and agents operate against the same model.
worker connection + communication management
manages worker connections, discovery, routing, and serialization, so an agent is a worker that can, with permission, act on every part of the system.
do i give up my current harness?+

no. run it as a worker. your harness keeps its interface; iii becomes the system underneath it, so the tools it calls are real functions and the work it starts outlives the turn.

is this MCP?+

no. functions with live, published schemas are the contract, and one protocol replaces a per-tool server for each integration. it's software that works, not a config file pointed at a vibe.

what happens when the agent's turn ends?+

the work doesn't. triggers are durable and replay engine-side; workers reconnect and re-register invisibly. a turn is just one cause among many — cron, state, and events keep going without it.

do i lose my model choice or my keys?+

no. model calls route through the llm-router worker on the engine. adding a provider is a router config, and your keys stay in the engine's configuration — not in a harness process or a dotfile.

isn't a runtime heavier than a harness?+

base iii is about 50MB for an entire production-capable system, harness included — no external dependencies, no extra upkeep. you get the harness and the backend it builds on for roughly the footprint of a harness alone.
